# JaNovel 사용 검증용 프론트 구현 계획

목표: Figma의 주요 흐름을 자유 입력·브라우저 저장이 가능한 독립 프론트로 옮겨 실제 자소서 작성 흐름을 검증한다.

범위: 로그인/가입/재설정, 지원 목록·필터·달력, 공고 입력(링크·이미지·텍스트)·확인·수정, 회사별 채용 단계·일정, 문항 작성·추가, 기록 본문 보기·구절 비교, 초안·스냅샷·분기·병합, AI 피드백 후보 기록·채택, 제출 버전 선택·고정본.

인증·OAuth·공고 자동 추출·AI API는 연결 전 상태를 명시한다. 프론트 사용 검증을 위해 진입은 허용하되 실제 계정 인증으로 표시하지 않는다. 민감한 비밀번호는 보관하지 않는다. 자소서·지원 정보는 이 브라우저에 저장하며 JSON 내보내기를 제공한다. Figma 우측 인증 영역은 기능명·레이블·필수 안내만 둔다.

## 구조

- `frontend/`: React 19 + Vite, 별도 의존성과 잠금 파일. 원본 Docsa는 읽기만 한다.
- `src/model.js`, `seed.js`, `storage.js`: 문항별 불변 스냅샷, 브랜치별 작업장, 로컬 저장·입력 데이터 검증.
- `src/pages/`: 인증, 지원 현황·달력, 공고 입력·상세, 작성·비교·병합·제출본.
- `src/components/`: 공통 버튼·다이얼로그·아이콘·조절 핸들·그래프·AI 대화.
- 모델 테스트는 Node 내장 테스트 러너를 쓰고, 실제 화면은 브라우저에서 확인한다.

## 핵심 규칙

- 스냅샷 노드 클릭은 본문 읽기로 시작한다. 비교는 켜고 끌 수 있다.
- 최신 스냅샷에서 실제 내용 변경 시 해당 작업장으로 전환한다. 다른 초안이 있으면 덮어쓰지 않고 현재 초안 열기/새 분기를 선택한다.
- 중간 스냅샷의 실제 수정은 새 브랜치를 한 번 생성한다. 편집 모드 진입만으로 생성하지 않는다.
- 브랜치 데이터에는 작업장이 하나씩 있다. 그래프에는 변경 여부와 관계없이 각 브랜치의 작성 중 작업장을 표시한다.
- 병합은 현재안/새 브랜치 생성안을 선택할 수 있다. 원본 기록은 유지하며 병합 직후 새 스냅샷을 자동 생성하지 않는다.
- 제출본은 선택한 문항별 본문을 복제해 고정한다. 이후 초안 수정과 분리한다.

## 작업 순서와 완료 기준

1. [x] 모델 테스트를 먼저 작성하고 실패 확인 → 불변 기록·자동 분기·초안 충돌·두 병합 방식·고정본 분리 구현.
2. [x] 프론트 실행 환경과 로컬 저장 → 독립 설치·빌드 성공, 새로고침 뒤 입력 유지.
3. [x] 인증·지원 목록·달력·공고·상세 → 새 지원 등록부터 문항 작성까지 왕복, 일정과 채용 절차 수정.
4. [x] 작성·그래프·비교·분기·병합 → 실제 타이핑, 비교 대상 선택, 구절 반영과 두 결과 방식.
5. [x] AI 후보·제출본 → 외부 응답·수정안 붙여넣기·비교·채택, 고정본 생성·복사.
6. [x] 모델 테스트·프로덕션 빌드·대표 사용자 흐름 브라우저 검증, 실행 방법 문서화.

Ruling: 기존 작업 폴더의 새 `frontend/`에 구현한다. 사용자가 모든 기획·디자인·코드를 이 폴더에 모으도록 지정했고, 기존 Docsa 및 진행 중 디자인 파일과 충돌하지 않는 별도 경로다. Git 브랜치·커밋·푸시는 이번 작업에 포함하지 않는다.

- 작업 6: 양옆 접기/펼치기, 키보드 너비 조절, 그래프 펼치기/원형 지도, OAuth 연결 전 안내 및 가입 이메일 확인→계정 정보 화면 전환 확인. 대표 화면의 브라우저 오류/경고 0건.
- 날짜·시간 입력 검증에서 DOM 값과 폼 상태가 달라지는 상황을 확인하여 제출 시 FormData의 날짜·시간을 읽도록 수정하고 11.19 (목) 14:00 일정 저장을 재검증.
- 외부 인증·메일·AI API/MCP·URL 수집·OCR은 연결 전이며, 동작하는 것으로 표시하지 않는다. 이미지 업로드/백업 파일 불러오기의 전체 브라우저 조합과 모바일 작성기 전체 흐름은 이번 검증에 포함하지 않았다.

## 최종 별도 검토

새 검토자가 전체 frontend 코드를 읽고 발견한 3건을 수정했다.

1. 지연된 클립보드 요청 뒤 오래된 문항 객체가 최신 초안/스냅샷을 덮을 가능성 → 최신 상태에 메시지만 덧붙이는 갱신으로 변경. 누락 함수 실패 확인 → 추가 → 테스트 통과.
2. null 글자 수, 중복 문항, 잘못된 일정/제출본/메시지/기록 소유권 백업 허용 → 화면에서 소비하는 필드와 소유권/연결 검증. 거부하지 못하는 테스트 실패 → 수정 → 통과.
3. 같은 과거 기록을 기존 분기에 병합한 뒤 타이핑/삭제로 되돌리면 초안이 사라짐 → 초안이 기준으로 삼는 기록과 분기의 최신 기록이 다른 경우를 변경 상태로 유지. 실패 재현 → 수정 → 통과.

Ruling: 실제 AI 연결 전에는 외부 응답을 붙여넣도록 한다. 생성된 예시 답변을 실제 AI 결과로 혼동하는 비용을 피하며, 서비스 안에서 자동 응답받는 검증은 연결 단계까지 남는다.
철회한 결정: 변경 없는 초안을 그래프에서 숨기는 규칙은 원본 시안과 달라 2026-11-10 수정에서 제거했다. 모든 브랜치의 작업장 노드를 표시한다.
Ruling: 현재 폴더에 독립 프론트를 남기고 Git 통합·커밋·푸시는 하지 않는다. 원본 Docsa 변경을 피하지만 추후 백엔드/저장소 통합 작업은 별도 필요하다.

## Docsa 방식 병합 화면 수정

사용자 요청: 어색한 병합 아이콘과 ‘이 본문으로 시작’ 제거, 가운데 ‘병합할 본문’ 제목 변경, 비교 화면처럼 전체 본문을 보며 병합.

- 원본 `Docsa_FE/frontend/src/components/DocumentMergeView.tsx`, `editor-preview/diffRender.tsx`를 읽기만 했다. 공통 구간을 기반으로 좌우 변경 구절을 선택하는 동작과 3열 배치를 텍스트 모델에 맞춰 적용했다.
- 오른쪽 변경 카드 목록을 제거하고 양쪽 전체 본문에 변경 구절을 인라인으로 표시했다. 클릭·Enter·Space로 선택/해제하며 가운데 결과를 직접 수정할 수 있다. 직접 편집한 다른 구절과 앞뒤 문장을 보존한다.
- ‘이 본문으로 시작’을 제거했다. 가운데는 ‘결과’, 확정 버튼은 ‘병합하기’로 정리했다. 분기 이름·설명·위치 입력은 확정 다이얼로그에 모았다. 비교 버전 변경 시 작업 중인 결과를 즉시 버리지 않도록 확인한다.
- 기존 GitFork/GitMerge 대신 디자인 문서20에서 정한 공식 Lucide Split/Merge를 적용했다. 아래 방향, 18px, 선 두께1.25px를 브라우저에서 확인했다.
- 새 구절 선택 모델 테스트를 구현 전 실행해 실패를 확인했다. 양쪽 본문 복원, 부분 선택·해제, 추가/삭제·빈 구절, 반복 문구 위치, 직접 편집 보존 및 두 부모를 가진 병합 초안 전달까지 검증했다. 전체21개 테스트 및 빌드 통과.
- 브라우저에서 좌우 선택, 실제 텍스트 클릭, 키보드 선택, 직접 편집 뒤 다른 구절 반영, 비교 대상 변경 보호, 확정 다이얼로그 입력을 확인했다. 사용자 작업 기록을 바꾸지 않도록 브라우저에서는 새 병합을 최종 저장하지 않았고 저장 전달은 모델 통합 테스트로 확인했다.
