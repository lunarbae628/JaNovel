# 기록 정리 구현 계획

사용자 결정: 스냅샷은 아래 끝에서부터 삭제, 브랜치는 경고 후 삭제, 작성 중은 스냅샷을 남기고 닫는다. 기존 프론트에서 직접 구현한다. Git 커밋·원본 Docsa 수정은 범위 밖이다.

## 동작

- 스냅샷: 자식 스냅샷이나 다른 분기의 출발점·초안에서 참조하지 않는 분기의 마지막 기록만 삭제한다. 해당 분기의 초안 본문은 보존하고 부모만 이전 기록으로 이동한다.
- 브랜치: 스냅샷·초안 삭제 개수와 복구 불가를 확인창에서 알린다. 다른 분기의 본문은 유지하고 삭제된 부모 연결은 남아 있는 가장 가까운 조상으로 이어 준다. 마지막 한 분기는 유지한다.
- 작성 중: 변경이 있으면 이름·설명을 붙인 스냅샷을 만든 뒤 닫는다. 변경이 없으면 중복 스냅샷 없이 닫는다. 마지막 본문은 읽을 수 있으며 실제 수정 시 해당 분기의 작성 중이 다시 열린다.
- 삭제한 기록에 머무르던 선택·URL·비교 대상은 남아 있는 기록으로 이동한다. 제출본은 이미 본문을 복제하므로 영향을 받지 않는다.

## 작업·검증

- [x] `history-actions.js`, `model.js`: 삭제·닫기 순수 함수와 닫힌 초안 표시. 끝 기록, 분기·병합 참조, 미저장 본문 보존, 마지막 분기, 백업 검증, 삭제 후 스냅샷 번호를 테스트한다.
- [x] `Editor.jsx`: 본문 옆 삭제·닫기, 분기 관리 모달과 확인창. 삭제 후 선택·화면·URL을 동기화한다.
- [x] 전체 테스트·빌드 및 별도 localhost 원점의 합성 기록으로 UI를 검증한다. 실제 사용자의 127.0.0.1 기록은 삭제하지 않는다.

## 검증·보완

- 모델 테스트 41개 통과. 끝 기록 삭제 제한, 분기 삭제 후 병합 본문·부모 연결 보존, 백업 검증 및 닫기·다시 편집을 확인했다.
- 별도 localhost 원점 브라우저에서 중간 스냅샷 삭제 비활성화, 끝 스냅샷 삭제 확인창, 분기별 삭제 개수 경고·취소, 이름·설명이 있는 스냅샷 생성 후 작성 중 노드 닫힘을 확인했다. 실제 영구 삭제 버튼은 누르지 않았다.
- 다른 검토에서 발견한 변경 없는 새 분기의 중복 스냅샷, 삭제로 닫힌 초안이 재등장하는 문제, 빈 초안 닫기 실패를 각각 실패 테스트로 재현하고 수정했다.
- 반복 병합된 34개 스냅샷의 출처 경로를 매번 펼치던 문제는 방문한 기록을 중복 탐색하지 않는 방식으로 수정했다. 기존 코드에서 약 4초 걸려 실패하던 500ms 제한 회귀 테스트가 수정 후 통과했다.
- 브라우저 제어가 설정에서 비활성화되어 마지막 수정 뒤 브라우저 재검증은 중단했다. 위 동작 확인은 그 이전 관찰이며, 이후 보완은 모델 테스트와 빌드로 검증했다.
- 별도 검토는 사용 한도로 최종 보고 전에 중단됐다. 전달받은 네 문제를 모두 재현·수정했고 남은 범위는 직접 검토했다.

### 추가 결정

- 빈 본문은 스냅샷 생성 제한에 맞춰 스냅샷 없이 닫고, 빈 초안 자체와 이전 기록은 보존한다. 닫기 확인창에 이 예외를 표시한다.
- 변경 없는 새 분기는 자기 스냅샷이 없어도 같은 본문을 가진 출발 스냅샷을 재사용한다.
- 닫힌 분기의 스냅샷을 삭제해도 실제 편집 전에는 작업 노드를 다시 열지 않는다.

## 2026-11-12 병합 후 원본 작성 중 자동 닫기

- 사용자 요청에 따라 병합 화면 오른쪽의 ‘병합할 버전’을 from으로 해석한다. 병합 완료 시 이 원본 분기의 작성 중을 자동으로 닫는다. 왼쪽 기준 분기와 결과 분기의 작성 중은 유지한다.
- from 분기 자체를 결과 위치로 선택한 경우에는 결과 초안을 닫지 않는다.
- 과거 스냅샷을 from으로 고른 경우에도 원본 분기의 더 최신 미저장 초안을 별도 스냅샷으로 남긴 뒤 닫는다. 빈 초안은 텍스트 상태 그대로 보관한다.
- 병합 확인창에서 자동 닫기를 알린다. 다시 수정하면 해당 분기의 작성 중이 열린다.
- 새 분기·기존 분기 병합, 결과 위치와 원본이 같은 경우, 과거 기록과 최신 미저장 본문, 빈 초안의 회귀 테스트를 추가했다. 전체 46개 테스트와 빌드 통과.
