# 주제별 독립 작성안 구현 계획

목표: 문항 아래에서 주제별 작성안을 독립적으로 쓰고 수정 기록을 관리한다. 작성안·스냅샷·작성 중 본문을 자유롭게 비교하고 두 본문을 조합하면 새 작성안을 만든다. 사용자가 승인한 대화의 구상을 프론트에 구현한다.

구조: 기존 `branches`·`snapshots` 저장 형식과 ID를 보존한다. 신규 작성안은 부모 없이 시작한다. 합친 작성안은 독립된 첫 스냅샷과 두 원문의 고정 출처를 가지며 원본 초안·스냅샷을 변경하지 않는다. 기존 계보는 삭제하지 않고 화면에서 작성안별 기록으로 표시한다. 새 의존성은 추가하지 않는다.

1. `writing-options.js`, `writing-options.test.js`: 빈 작성안 생성·이름 수정·동일 작성안 내 과거 기록 편집·원문 보존 조합·출처 조회를 테스트 먼저 구현한다. 기존 저장 데이터와 백업 검증을 통과해야 한다.
2. `OptionHistory.jsx`, `Editor.jsx`, `styles.css`: 작성안 목록과 선택한 작성안의 단일 기록 목록, 새 작성안·이름 수정·삭제·공통 출처 표시를 연결한다. 두 비교 선택기는 모든 작성안의 기록을 지원한다. 과거 스냅샷을 편집해도 원본은 변하지 않는다.
3. `Merge.jsx`: 양쪽 구절 선택·가운데 편집은 유지하고 완료 시 새 작성안만 만든다. 기존 작성안에 덮어쓰기·원본 초안 자동 닫기는 이 화면에서 제거한다.
4. 전체 Node 테스트·프로덕션 빌드·브라우저 신규 작성안→스냅샷→다른 안→비교→조합→출처·새로고침 보존을 확인한다. 실제 사용자 데이터는 읽기 전용으로 확인하고 변경 시연은 별도 로컬 테스트 주소에서 수행한다.

주의할 입력: 빈 작성안, 스냅샷 없는 초안끼리 조합, 같은 작성안의 서로 다른 기록, 기존 미저장 초안과 과거 기록 편집 충돌, 참고한 원본 삭제 후 출처 보존. 제출본과 AI 대화의 기존 기능은 보존한다.

검증 결과:
- 테스트 65개 통과. 프론트 및 기획 문서 빌드 성공.
- 별도 localhost 테스트 공고에서 작성안 이름 수정 → 첫 스냅샷 → 빈 새 작성안 → 초안 비교 → 스냅샷 대상 선택 → 전체 본문 추가·연결 문장 편집 → 새 작성안 생성 → 새로고침 → 참고 원문 열기를 확인했다.
- 과거 기록을 수정해도 작성안 개수는 유지되며 기존 초안과 충돌하면 확인창이 나타난다. 다른 작성안의 미저장 초안은 조합 후에도 남는다.
- 독립 검토에서 비교 대상 변경 후 새로고침하면 이전 작성안이 열리는 문제를 발견했다. 비교 양쪽 대상을 주소에 보존하도록 수정했고 스냅샷·초안, 초안·초안 비교를 테스트 및 브라우저에서 다시 확인했다.
- 기존 사용자 주소인 127.0.0.1의 본문·기록은 테스트 데이터로 교체하지 않았다. 원본 Docsa 코드는 수정하지 않았다.

구현 판단: 기존 분기·병합 함수는 과거 데이터 호환성과 기존 테스트를 위해 유지한다. 현재 프론트는 독립 작성안과 원본을 변경하지 않는 새 조합 함수를 사용한다. 스냅샷 번호는 기존 문항 전체 번호를 보존해 과거 링크가 달라지지 않게 했다.
