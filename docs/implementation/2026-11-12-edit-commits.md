# 스냅샷을 바로 편집하는 흐름

사용자 요청: 기본 그래프에는 확정 스냅샷만 표시한다. 버튼 없이 스냅샷 본문을 수정하면 작성 중이 생기고, 중간 스냅샷을 수정하면 분기한다. 원문과 정확히 같아지면 작성 중을 없앤다. 앞서 논의한 병합도 결과 스냅샷을 바로 생성한다.

1. 모델 → 검증: 변경 없는 초안은 숨김, 스냅샷 생성 후 작성 중 닫힘, 원문 복귀 시 자동 분기 정리, 기존 미저장 초안 보호, 병합 결과 스냅샷·두 부모 보존.
2. 편집 화면 → 검증: 최초·재진입 시 최신 스냅샷, 본문 직접 입력·IME·삭제·되돌리기 시 편집칸 유지, 작성 중 노드 출현·소멸, 중간 기록 분기, 스냅샷 확정 후 해당 기록 선택.
3. 병합 화면 → 검증: 이름·설명은 결과 스냅샷에 저장, 결과 기록으로 이동. from 작성 중 자동 닫기 유지.
4. 기존 데이터 → 검증: 실제 미저장 초안은 숨기거나 삭제하지 않고 유지한다. 원본 Docsa와 Git 작업은 범위 밖이다.

자동 분기는 자동 편집으로 생성됐고 아직 자기 스냅샷이 없는 경우만 원문 복귀 시 제거한다. 명시적으로 만든 분기·스냅샷을 만든 분기는 유지한다. 임시 분기 제거 시 다른 분기의 미저장 본문은 바꾸지 않는다.

## 구현·검증 결과

- `visibleGraphRecords`는 실제 변경이 있는 열린 초안만 표시한다. 변경 없는 기존 데이터는 표시만 정리하며 본문·스냅샷을 삭제하지 않는다.
- `autoFromId`로 자동 편집 분기의 출처를 보관한다. 원문 복귀 시 자기 스냅샷이 없는 자동 분기만 제거하며, 스냅샷 확정 시 이 임시 표식을 해제한다. 백업 검증에도 반영했다.
- 편집칸은 스냅샷·작성 중 전환 시 동일한 textarea를 유지한다. 실제 브라우저에서 한 글자 입력과 기본 되돌리기 단축키로 원문 복귀·커서 유지·노드 소멸을 확인했다. 한글 IME 조합 입력은 별도로 자동 검증하지 않았다.
- 중간 스냅샷 직접 편집 → 자동 분기 → 되돌리기 → 자동 분기 제거를 브라우저에서 확인했다. 그동안 다른 분기의 미저장 본문은 유지됐다.
- 병합 결과의 두 부모·이름·설명을 확정 스냅샷에 저장하며 결과 `snapshotId`로 이동한다. 브라우저에서 병합 직후 작성 중 0개, 추가 수정 후 작성 중 생성, 스냅샷 확정 후 0개와 새로고침 후 선택 유지를 확인했다.
- 검증은 별도 localhost 데이터에서 수행했다. 사용 중인 127.0.0.1 데이터는 검증 입력으로 바꾸지 않았다.
- 전체 테스트 56개·프로덕션 빌드 통과. 최종 브라우저 콘솔 오류·경고 없음. 화면 기록: `_workspace/2026-11-12-direct-edit/commit-editor.png`.

## 수동 닫기 제거·분기 색 구분 개선

- 사용자 요청으로 본문과 비교 화면의 수동 작성 중 닫기 버튼·확인창·연결 함수 및 사용하지 않는 닫기 모델 함수를 제거했다. 원문 복귀·스냅샷 확정·병합 원본의 자동 닫기는 유지한다.
- 파랑·주황·보라·청록 등을 사용하며 기존 저장 데이터의 자동 배정 색도 표시 시 변환한다. 분기 순서값을 기준으로 색을 유지해 다른 분기를 삭제해도 색이 바뀌지 않는다. 기존 사용자 지정 색은 유지한다.
- 선을 조금 선명하게 하고, 노드와 버전 번호에 같은 분기 색을 사용한다. 지도형 그래프·분기 관리에도 같은 색을 적용한다.
- 사라진 수동 닫기 기능만 검사하던 테스트 4개를 정리했다. 나머지 52개 테스트·빌드 통과. 브라우저에서 실제 작성 중 상태에도 닫기 버튼이 없고 기존 분기 3개의 색이 각각 다르게 표시됨을 확인했다.
- 후속 외형 피드백으로 버전 번호 색은 중립색으로, 선·원 크기는 이전의 가는 스타일로 되돌렸다. 서로 다른 분기 색상은 선·원에만 유지한다. 실제 사용 중인 여러 분기의 화면에서 읽기 전용으로 확인했다.
