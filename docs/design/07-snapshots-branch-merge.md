# 스냅샷·분기·병합

2026-11-01 · 사용자 요청에 따른 화면 확장 · 실제 제품 구현 전

## 화면과 용어

문항 선택 Q1·Q2는 가운데 작성 섹션의 비교·병합·스냅샷 도구와 한 줄에 둔다. 문항 선택만을 위한 전체 폭의 빈 줄은 제거했다. 이 도구 줄은 우측 채팅의 폭을 사용하지 않으며, 패널 접기 상태에 따라 가운데 폭 안에서만 배치된다. 휴대폰에서는 문항 선택을 기존 버전·작성·채팅 전환 줄에 함께 배치한다. 기존 ‘저장’ 버튼의 사용자 노출 명칭은 ‘스냅샷’으로 바꾼다.

스냅샷은 선택한 문항의 의미 있는 답변 기록이다. 키 입력마다 남기는 기록이나 전체 자소서 제출본과 구분한다. 현재 부모 스냅샷과 같은 내용이면 중복 생성하지 않는다. 새 분기의 첫 스냅샷은 내용이 같아도 분기 관계를 남길 수 있다.

## 이름과 설명

스냅샷·분기 생성 시 작은 입력창에서 이름과 설명을 선택적으로 적는다. 일반 스냅샷, AI 수정안 적용과 병합 스냅샷에 같은 입력 방식을 쓴다. 이름은 최대 60자, 설명은 최대 500자다. 취소나 Escape는 기록과 본문을 바꾸지 않는다. 이름을 비워도 스냅샷의 v번호는 남고, 분기에는 기본 이름을 부여한다.

스냅샷 이름은 그래프의 번호 아래와 비교·병합 선택지에 표시한다. 설명은 기록을 선택했을 때 확인하고, 그래프의 툴팁에도 표시한다. 분기의 이름·설명은 해당 갈래에서 작성할 때 표시한다. 긴 이름은 그래프에서 줄임표를 쓰고 전체 내용은 툴팁과 접근성 이름으로 제공한다.

답변 내용이 현재 스냅샷과 같으면 입력창에 기존 이름·설명을 채워 주고, 확인 시 해당 메타데이터만 수정한다. 본문이 바뀌었거나 새 분기의 첫 기록이면 새 스냅샷을 만든다. 분기 이름·설명은 문항 안의 갈래에 속하고 스냅샷 이름·설명은 개별 기록에 속한다. 입력창을 연 뒤 작성본이 바뀌면 확정을 막는다.

회사명 헤더의 ‘지원하러 가기’는 제공된 팔레트의 Graphite(#302B27)로 강조해 파란 스냅샷 버튼과 구분한다. 링크가 없어 비활성화된 예시는 옅은 차콜(#6E6965)을 사용한다.

## 여기서 분기하기

왼쪽 그래프에서 스냅샷 선택 → 가운데 비교 화면의 ‘여기서 분기하기’ → 분기 이름·설명 입력 → 선택한 스냅샷 내용으로 새 갈래에서 작성 → ‘스냅샷’에서 기록 이름·설명 입력 순서다.

새 갈래의 부모는 선택한 스냅샷이며, 기존 갈래와 다른 위치에 표시한다. 분기 후에는 도구 줄에 시작 스냅샷을 표시하고 그래프의 작성 중 노드에도 새 분기임을 알린다. 분기 시작과 스냅샷 생성은 구분한다. 분기 전에 작성 중인 변경이 있으면 먼저 스냅샷을 남기도록 안내하며 기존 초안을 덮어쓰지 않는다.

## 병합 화면

가운데 ‘병합’에서 같은 문항의 스냅샷 두 개를 고른다. 문단별 좌우 선택을 제공하고, 동일한 문단은 한 번만 표시한다. 다른 문단은 명시적으로 선택하기 전까지 확정할 수 없다. 한쪽에만 문단이 있으면 다른 쪽은 ‘문단 없음’으로 표시한다.

선택을 마친 뒤 결과를 직접 수정할 수 있다. 직접 수정 중에는 원본 선택과 문단 선택을 잠가 결과가 조용히 덮어써지지 않게 한다. ‘직접 수정 초기화’를 누르면 선택한 문단으로 만든 결과로 되돌아가고 선택을 다시 바꿀 수 있다.

‘병합 스냅샷’은 선택한 두 스냅샷을 부모로 가진 새 기록을 만든다. 원본 스냅샷과 다른 문항의 이력은 바꾸지 않는다. 결과가 비었거나 같은 스냅샷을 두 번 고른 경우에는 확정할 수 없다. 병합 시작 당시 작성본과 현재 작성본이 다르면 확정을 막는다. 취소는 스냅샷을 만들거나 현재 답변을 바꾸지 않는다.

## 이번 방식과 구현 범위

이번 초안은 사용자가 문단을 골라 결과를 확인하는 수동 병합이다. 문단은 위치 기준으로 나란히 보여 주므로 삽입·재배치된 문단은 결과 편집에서 정리해야 한다. 공통 조상을 계산하는 3-way 병합이나 자동 충돌 해결로 표시하지 않는다. 자소서 내용 선택을 직접 검토할 수 있도록 이 방식을 택했다. 실제 자동 병합과 충돌 단위는 Docsa 코드를 검토한 뒤 정한다.

와이어프레임의 로컬 데이터에는 기존 부모 외에 병합 부모를 추가했다. 그래프에는 두 연결선을 표시한다. 실제 API·DB·MCP 계약이나 원본 Docsa 코드는 변경하지 않았다. 문항 간 병합, 갈래 이름 관리, 그래프 직접 편집과 영속 저장은 포함하지 않는다.
