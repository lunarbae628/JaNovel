# Figma 화면 흐름 정리와 병합 방식 비교

2026-11-10. 병합 정책은 아직 결정하지 않는다. 현재 시안과 Docsa 구현에 따른 시안을 모두 남기고 비교한다.

## 화면 찾기

[Figma 화면 흐름 안내](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=144-207620)에서 시작한다.

- `01 · 화면 흐름`: 핵심 화면 24개를 인증 → 지원 현황·달력 → 공고 등록 → 작성·AI → 기록 비교·분기·병합 → 병합안 비교 순서로 배치한다.
- 연결된 반복 상태와 팝업 314개는 같은 페이지 오른쪽 `80 · 상세 상태 / 클릭 검증용`에 보관한다. 페이지를 나눠 기존 프로토타입 전환이 끊기는 것을 피한다.
- `90 · 이전 시안`: A/B/C와 사용하지 않는 과거 메뉴 등 19개를 보관한다.
- `99 · 공통 컴포넌트`: 입력·버튼·아이콘·패널 변형 87개 묶음을 옮긴다. 기존 컴포넌트·인스턴스 ID는 보존한다.
- 화면을 삭제하거나 복제해서 정리하지 않는다. 안내 보드의 카드에서 각 단계의 대표 화면으로 이동한다.

## OAuth 화면

Google·카카오 버튼을 로그인과 가입 시작 화면에 추가했다. 이메일 가입은 그대로 유지한다. Google 공식 배포 아이콘과 카카오 공식 SVG 심볼을 사용한다. 서비스 로그인과 외부 AI 연결은 별개다.

- [Google 공식 디자인 가이드](https://developers.google.com/identity/branding-guidelines)
- [카카오 공식 디자인 가이드](https://developers.kakao.com/docs/ko/kakaologin/design-guide)

로컬 버튼은 인증 이동 안내만 표시한다. 실제 OAuth 제공자 등록, 리다이렉트, 세션 처리, 기존 이메일 계정과의 연결 정책은 구현 범위에 포함하지 않았다. Figma 버튼은 로그인 성공 뒤 화면을 보여주는 프로토타입 연결이다.

## 병합안 두 가지

| 구분 | 현재안 — 유지 | Docsa안 — 추가 비교안 |
| --- | --- | --- |
| 병합 결과 | 기존 흐름의 v4로 이어짐 | 새 브랜치와 별도 작성 중 생성 |
| 원본 브랜치 | 기존 예시 유지 | 두 원본 브랜치와 작업장 유지 |
| 병합 직후 | 현재 예시의 저장된 병합 기록 | 스냅샷 없이 두 원본에서 새 작업장으로 연결 |
| 스냅샷 이후 | 기존 흐름의 기록으로 표시 | 새 브랜치 첫 스냅샷과 그 뒤의 작업장으로 표시 |

- [현재안](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=113-193951)
- [Docsa안: 병합 직후](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=144-206941)
- [Docsa안: 첫 스냅샷 생성 후](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=144-207273)

Docsa `MergeMySqlTxService.createMySqlPart`는 `createBranch(...baseCommit)`, `updateMergeTargetCommit(targetCommit)`, `createSave(newBranch, ...)`를 호출한다. 병합 API 단계에서 새 커밋을 생성하지 않는다. `MergeRequest`도 ‘새 브랜치 작업장 생성’으로 명시되어 있다. 기존 시안의 자동 스냅샷처럼 보이는 의미를 Docsa안에 그대로 적용하지 않는다.

로컬 검토 화면 하단에서 병합 방식을 바꾼다. Docsa안에서는 병합 단계와 사례를 고를 수 있다. 같은 브랜치의 두 기록, 병합 결과의 재병합, 스냅샷 없는 새 분기를 예시로 준비한다. 브랜치 색은 선택해도 유지하고, 병합의 두 진입선은 각각 출발 브랜치 색으로 표시한다.

## 그래프 처리 원칙

- 관계는 문항 ID·브랜치 ID·기록/작업장 ID로 구분한다. 이름이나 화면 좌표를 식별자로 삼지 않는다.
- 부모가 두 개면 두 연결을 보존한다. 원본 브랜치를 임의로 종료하지 않는다. 동일한 부모 ID가 중복되면 선은 하나로 표시하되 원본 메타데이터는 잃지 않는다.
- 빈 브랜치는 분기 시작 기록에서 작업장으로 연결한다. 반복 병합은 새로운 브랜치를 추가하고 기존 브랜치의 색을 바꾸지 않는다.
- 좁은 사이드바에서는 한 행에 한 기록을 배치한다. 많은 브랜치는 가로 공간과 패널 확대·전체 보기를 사용한다. 긴 이름은 한 줄 말줄임으로 처리하고 전체 정보는 별도로 제공한다.
- 실제 서버 데이터의 누락된 부모·순환·잘못된 문항 연결은 정상 기록처럼 조작해 그리지 않는다. 검증 오류·복구 가능한 누락 표기가 필요하며, 이 부분은 실제 그래프 구현 시 추가할 범위다. 모든 가능한 데이터 조합을 검증했다고 보지 않는다.

기존안과 Docsa안은 같은 기능 정책으로 합치지 않는다. 사용자가 선택하기 전까지 두 대안으로 보관한다.

## 정리 후 점검

- 핵심 화면 24개 사이의 겹침 0건.
- 프로토타입 동작 6,525개에서 사라진 대상 0건, 페이지를 잘못 건너가는 이동 0건.
- 공통 부품 이동 뒤 끊어진 인스턴스 참조 0건.
- 작성·비교 상태 217개에 양쪽 경계 핸들을 일관되게 표시했다. 자유로운 너비 조절은 브라우저 동작 시안에서 제공한다.
- 브라우저에서 현재안의 3개 작업장 유지, Docsa안의 4개 작업장, 스냅샷 전후, 반복 병합의 5개 작업장, 빈 분기와 200개 기록의 기록형·지도형 표시를 확인했다.
- 좁은 로그인 화면에서 가로 넘침이 없고 두 OAuth 버튼이 46px 높이를 유지했다. OAuth를 눌러도 실제 제공자에 접속하거나 계정을 연결하지 않는다.
