2026-11-08 · 14번 검토본 이후 변경 · 디자인 검토용

> 후속 변경: [16번 문서](16-snapshot-working-draft-comparison.md)에 따라 노드 선택 시 왼쪽 스냅샷과 오른쪽 비교 대상을 함께 표시한다. 오른쪽에는 미스냅샷 작성 중 초안도 포함한다. 아래의 단일 본문 보기 설명은 이전 검토 상태다.


## 이번에 바꾼 흐름

- ‘제출본’은 ‘제출 버전’으로 표시한다. 문항별 스냅샷을 묶어 지원에 사용한 내용을 보관하는 기능이다. 외부 지원 링크를 누르는 것만으로 제출 완료 처리하지 않는다.
- 그래프 기록을 누르면 팝업 없이 해당 버전 본문으로 바로 이동한다. 본문 상단의 비교·병합·분기에서 다음 작업을 선택한다. 비교·병합은 상대 기록 선택으로 이어지며, 읽는 기록을 그래프에서 강조한다. 기록 본문과 현재 작성본을 구분한다.
- 비교 화면의 전용 하단 작업 줄을 없애고 버전 이름과 글자 수를 본문 위에 둔다. 비교 대상 선택은 그래프에서 처리한다. 변경된 구절만 강조하고 빨강을 사용하지 않는다.
- 병합은 원문·병합 결과·다른 기록의 3열이다. 두 변경 구절을 각각 고르는 상태와 이름·설명을 입력하는 병합 스냅샷 창을 연결했다.
- 왼쪽 기록과 오른쪽 채팅을 각각 접을 수 있다. 접힌 패널에는 펼치기 방향의 화살표를 두고 가운데 작성 영역을 넓힌다.
- 달력은 날짜 셀, 오늘 표시, 마감·면접·과제 일정 카드로 구분한다. 이전 달·오늘·다음 달은 개별 버튼이다. 일정 카드에서 상세·수정으로 이동한다.
- 공고 입력 방식, 등록·작성, 문항 전환, 지원 목록·상세·단계 선택, 일정, 스냅샷·분기·복원, AI 후보 검토, 제출 버전 화면의 조작에 Figma 전환을 설정했다.

## 연결 검증과 범위

로컬 Talk to Figma 플러그인에 `janovel_set_reactions`, `janovel_inspect_reactions`를 추가해 실제 Figma 전환을 쓰고 다시 읽었다. 기존 도구에 전환 쓰기가 없었던 14번 문서의 제약은 이 방법으로 해결했다. 단순히 호버 효과가 있다는 이유로 클릭 연결 완료로 세지 않는다.

최종 읽기 검사에서 전환 2,022개의 목적지·종류가 저장한 설정과 일치했고, 검사 대상 버튼의 미연결과 불일치는 각각 0건이었다. 대표 경로 6개는 기대한 끝 화면까지 연결됨을 확인했다. 렌더링 텍스트의 폰트는 Noto Sans KR이다.

검사 소스는 `scripts/figma/verify-prototype.mjs`다. 전환 목적지와 종류를 읽은 결과와 대조하고, 그래프 → 기록 본문 → 비교/병합, 분기, 공고 등록, AI 후보 채택, 제출 버전의 대표 경로를 검사한다. 선택된 문항처럼 이미 활성화된 탭은 자기 화면으로 이동시키지 않는다. 검사 기록과 이미지, 전환 원본은 `_workspace/2026-11-08-interactions/`에 둔다.

앞선 검토에서는 네이티브 Figma 미리보기의 기록 메뉴 표시를 확인했다. 후속 사용자 피드백으로 그 메뉴를 우회하고 본문으로 직접 이동하게 바꿨다. 최신 변경은 전환 설정의 목적지와 본문 상단 버튼을 다시 읽어 검증하고 캡처로 배치를 확인했다. 모든 경로를 포인터로 왕복한 UI 검증까지 완료했다는 뜻은 아니다. 비교 본문의 잘림, 달력 마감 글자 대비, 접힌 패널의 너비·화살표는 캡처 후 보완했다.

현재는 유한한 예시 상태를 이동하는 디자인 프로토타입이다. 입력 필드의 자유로운 타이핑, 실제 문서 보관, 선택 결과의 영속성, 클립보드 복사, 이미지 업로드·추출, AI 호출·응답은 제품 구현이 필요하다. 과거 기록과 일부 예외 경로는 대표 예시로 이어지며 모든 데이터 조합을 재현하는 것은 아니다. 외부 지원 링크도 예시 주소다.

Figma 편집기에 ‘변경사항이 로컬에 저장됐으며 재연결 후 동기화된다’는 표시가 관찰됐다. 로컬 파일의 전환 읽기 검증과 별개로 공유 링크에 최신 변경이 반영됐는지는 동기화 후 확인해야 한다. 저장 경고가 남은 상태에서 파일을 새로고침하지 않는다.

## 다음 검토

사용자는 기존 파일에서 작성 → 노드 선택 → 해당 본문 → 비교/병합 → 스냅샷 → 지원 현황 → 달력을 우선 확인한다. 조작 방식과 시각 검토를 마친 다음, 고객의 AI를 웹 채팅에서 사용하는 연결 실험과 구현 계획으로 넘어간다. 이번 작업으로 제품의 AI 연결이나 문서 저장 구현이 완료된 것으로 표시하지 않는다.
