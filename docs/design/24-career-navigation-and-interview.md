# 취업 준비 탐색 구조와 면접 화면

2026-11-13. 사용자가 Figma에서 먼저 검토하도록 요청한 디자인 제안이다. 프론트 구현 범위를 확장하거나 기존 데이터를 변경하지 않는다.

## 조사한 UX 근거와 적용 판단

- [NN/g: 왼쪽 세로 탐색](https://www.nngroup.com/articles/vertical-nav/)은 넓거나 확장되는 정보 구조에 유리하지만 가로 공간을 차지한다고 설명한다. 따라서 관리 화면에서는 아이콘과 읽을 수 있는 이름을 함께 표시하고, 이미 세 영역이 있는 작성 화면에는 큰 전역 메뉴를 덧붙이지 않는다.
- [Carbon: UI shell left panel](https://www.carbondesignsystem.com/building-blocks/core/components/ui-shell-left-panel/guidelines)은 항목 간 전환이 빈번한 경우 왼쪽 탐색을 사용할 수 있으며 3단계 이상의 중첩을 피하도록 안내한다. 세 가지 실제 작업을 한 단계로 노출하고 회사별 작업은 화면 안에 둔다.
- [W3C APG: 탐색 링크와 펼침](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)에 따라 후속 구현에서 일반 탐색 링크에 불필요한 `menu` 역할을 부여하지 않는다. 현재 위치, 키보드 초점, 메뉴 접힘 상태를 구분한다.
- 로컬 디자인 가이드의 탐색 검색에서 현재 위치 표시·딥링크 원칙을 확인했다. 자동 추천된 랜딩 페이지형 단계 배치·다른 색상·서체는 제품과 맞지 않아 채택하지 않았다. 기존 Noto Sans KR, 무채색 표면, French Blue 포인트를 유지한다.

아래는 위 원칙을 이 제품에 적용한 설계자의 판단이며, 사용자 실험으로 입증된 결과는 아니다.

## 공통 메뉴

`지원 현황 / 일정 / 면접 준비`를 216px 왼쪽 패널에 둔다. 메뉴 이름과 얇은 Lucide 벡터 아이콘을 함께 표시한다. 선택된 메뉴는 바탕색과 왼쪽 표시선으로 구분한다.

최근 작성한 회사는 보조 바로가기이며 전체 회사 목록을 복제하지 않는다. 메뉴 하단에는 설정·계정을 둔다. 알림·공고 추천·이력서·제출본을 각각 별도의 최상위 메뉴로 늘리지 않는다.

지원 현황은 목록이 기본이다. 회사마다 단계가 다르기 때문에 고정된 ‘서류→1차→2차’ 칸으로 모든 지원을 강제로 이동시키는 보드를 기본으로 삼지 않는다. 목록 항목은 사용자가 요청한 대로 바로 자소서 작성으로 이동한다. 일정과 단계 수정은 회사의 공고 정보에서 접근한다.

작성 화면은 기존 기록·본문·AI 대화 구성을 보존한다. 관리 화면으로 돌아가는 경로를 유지하고, 공통 메뉴를 넣더라도 기본은 접힌 상태로 후속 검토한다. 이번 작업에서 기존 작성 화면 전체를 다시 생성하지 않는다.

## 면접 흐름

1. 면접 준비 목록에서 회사를 고른다. 예정된 면접과 연습 기록을 구분한다.
2. 실제 제출본과 해당 채용 공고를 확인한다. 제출본이 없으면 현재 작성본을 쓴다는 사실을 명시하고 사용자가 선택한다.
3. 예상 질문에는 출처를 표시한다. 사용자가 질문을 추가·수정할 수 있어야 한다. 생성된 질문은 실제 면접 출제 사실이나 확률을 뜻하지 않는다.
4. 예상 질문 페이지와 분리된 모의면접 모드에서 음성으로 질문을 듣고 답변한다. 면접 화면에는 타이핑 답변 입력을 두지 않는다. 질문과 음성 전사는 읽기용으로 표시한다.
5. 종료 후 질문·음성 전사·피드백을 복기한다. 답변 검토는 구체성·근거·직무 연결과 추가 질문을 중심으로 하며 합격 점수를 만들지 않는다. 자소서 수정이 필요하면 작성 화면으로 돌아간다. 연습이 기존 제출본을 수정하지 않는다.

사용자 결정으로 ‘텍스트 연습을 먼저 만든 뒤 음성 추가’ 제안을 철회했다. 예상 질문 정리 페이지에서는 질문을 추가·수정하고 근거를 확인한다. 모의면접 모드는 별도 시작 설정, 음성 입력 상태, 대화 전사, 일시정지·종료, 복기 흐름으로 설계한다. 진행 중에는 넓은 관리 메뉴를 숨겨 음성 대화에 집중하게 한다. Voice API 제공자·한국어 인식·응답 지연·권한·비용은 구현 전에 확인하며 Figma의 파형·전사·피드백은 실제 음성 분석 결과가 아닌 시안이다.

## 캘린더의 개인 할 일

지원 일정은 회사·전형과 연결되며 개인 할 일은 회사와 무관한 별도 항목이다. 캘린더와 선택 날짜 상세에 두 종류를 함께 표시한다. 개인 할 일에는 체크박스를 사용하고 지원 마감·면접·과제는 일정 종류를 표시한다. 색만으로 종류·완료 여부를 구분하지 않는다.

`추가`에서 지원 일정과 개인 할 일을 선택한다. 개인 할 일은 제목과 날짜를 입력하고 시간을 선택적으로 지정하며, 시간 없는 항목은 종일로 취급한다. 완료와 완료 취소는 지원 상태에 영향을 주지 않는다. 반복·알림·외부 캘린더 동기화는 추가하지 않는다.

## 제외한 기능

사용자가 경험·자료 보관함을 제외했다. 최초 제안에서 만든 해당 화면과 메뉴는 제거하고, 독립적인 작성안·스냅샷 비교와 해당 지원 건의 제출본 기반 면접에 집중한다. 개인 AI가 허용된 자료를 참고하는 기술적 요구와 별도의 경험 관리 제품을 만드는 것은 구분한다.

## 시안과 확인 범위

원본 디자인은 보존하고 `07 · 취업 준비 / 전역 메뉴와 면접` 구역에 대표 관리 화면과 면접 흐름을 모은다. 데이터는 모두 디자인용 예시다. 글꼴·본문 잘림·화면 경계·이미지로 평면화되지 않았는지와 연결 목적지를 검사하고 대표 화면을 시각 검토한다.

실제 데이터 저장, 인증, AI 연결, 음성 녹음, 자료 업로드와 질문 생성은 이번 작업의 완료 조건이 아니다. Figma 클릭 전환과 정적인 상태 표현은 실제 기능 구현과 구분한다.
