# 촘촘한 Git 로그형 그래프 시안

2026-11-10. 사용자가 제공한 IDE Git 로그 스크린샷의 행 배치와 좁은 브랜치 간격을 참고한 추가 검토안이다. 기존 지도형과 원본 화면은 보존한다. 서비스의 무채색 영역과 파란 포인트를 유지한다.

## 배치

- 한 기록을 높이 32px의 한 행으로 배치한다. 왼쪽에 작은 원과 분기·병합 경로, 오른쪽에 버전 번호와 이름을 표시한다.
- 브랜치 간격 14px, 노드 지름 7px. 같은 깊이의 기록도 서로 다른 행에 두어 이름이 겹치지 않는다.
- 시간·부모 관계는 기존 방향대로 위에서 아래로 이어진다. 분기는 부모 직후 갈라지고, 병합은 대상 기록 직전에 합류한다.
- 기본 사이드바 208px, 넓혀 보기 400px. 기록이 많으면 세로 스크롤로 탐색하며 선택한 기록으로 돌아갈 수 있다.
- 기본 흐름은 파랑 `#274690`, 두 갈래는 청록 `#39816F`, 황갈색 `#A4753E`으로 구분한다. 브랜치 선과 노드의 고유색을 맞추고, 선택해도 유지한다. 병합선은 출발 브랜치 색으로 대상 노드까지 이어진다. 선택은 옅은 회색 행 배경과 같은 브랜치 색의 바깥 링으로 표시한다. 작성 중 노드는 같은 색의 속 빈 점선 원으로 구분한다.
- 긴 이름은 한 줄 말줄임으로 표시한다. 브라우저 시안에서는 툴팁과 기록 정보에서 전체 이름·메시지를 확인한다.

실제 제품에서는 색을 브랜치 ID에 연결해 화면 위치가 바뀌어도 유지해야 한다. 현재 시안은 고정된 브랜치 예시의 색을 사용한다. 선의 연결·버전 이름도 함께 표시하므로 색만으로 관계를 설명하지 않는다.

## 산출물과 범위

- [Figma 기본 기록형](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=113-193951), [넓힌 기록형](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=113-194243): 편집 가능한 대표 화면 두 개. 전체 보기 버튼은 두 화면 사이를 연결한다. 새 기록 행의 개별 본문 전환은 아직 이 추가 Figma 시안에 연결하지 않았다.
- 로컬 동작 시안의 하단 ‘기록형 / 지도형’으로 두 방식을 비교한다. 기록 클릭 시 선택과 비교 헤더가 바뀐다. 본문은 기존 고정 예문으로, 실제 기록 데이터나 저장 기능은 연결하지 않았다.
- 200개 예시는 세로 스크롤·선택 위치 이동 검토용이며 성능 벤치마크는 아니다. 실제 제품에서 기록이 매우 많으면 행 가상화를 검토한다.

## 확인

- Figma 두 화면 모두 9개 행, 행 높이 32px와 편집 가능한 텍스트를 확인하고 PNG로 검토했다.
- 브라우저에서 200개 기록, 선택 기록으로 이동, 208→400px 확장, 긴 이름의 말줄임을 확인했다.
- 긴 이름이 사이드바를 강제로 늘리던 현상을 고쳤다. 패널 너비를 유지하고 제목만 줄여 표시한다.
- 지도형의 선택 위치 중심 이동·125% 기본 배율은 유지한다.

## 재생성

동작 시안은 `node scripts/wireframes/build-graph-map-review.mjs`로 빌드한다. 설치된 Docsa 의존성을 읽기만 하고 원본 코드는 수정하지 않는다. 상세 실행 방법은 21번 문서를 따른다.

Figma 도구는 `python3 scripts/figma/install-product-tools.py` 후 기존 플러그인을 연결하고 `node scripts/figma/compact-log.mjs CHANNEL`을 실행한다. `_workspace/2026-11-10-graph-map/log-state.json`에 기록된 화면이 있으면 재사용한다. 이 파일이 없는 다른 환경에서는 추가 대표 화면 두 개를 만든다.
