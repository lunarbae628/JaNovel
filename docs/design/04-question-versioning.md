# 문항 선택과 문항별 버전 그래프

2026-11-01 · 최신 화면·버전관리 기준 · 제품 구현 전

## 사용자 결정

이전 시안은 전체 문항 묶음에 하나의 그래프를 연결했다. 사용자는 문항별로 버전 기록이 가능해야 한다고 요청했다. 처음에는 사이드바에서 문항을 선택했으나, 등록한 긴 문항이 좁은 영역에서 잘리는 것을 보고 문항 선택을 사이드 밖으로 옮기도록 요청했다.

최신 화면에서는 가운데 도구 줄의 Q1·Q2에서 문항을 선택한다. 탭에는 번호만 표시하고 전체 문항은 접근성 이름과 툴팁에서 확인한다. 본문에는 전체 문항과 바로 옆 글자 수를 표시한다. 왼쪽에는 선택한 문항의 버전 그래프만 남긴다. 가운데 제목·작성 답변·비교 대상과 오른쪽 AI 대화는 같은 문항으로 바뀐다. 사용자 색상 팔레트와 3열 구조는 유지한다.

문항 탭과 비교·병합·스냅샷 도구를 가운데 작성 섹션의 한 줄에 둔다. 문항 선택용 전체 폭의 별도 줄은 제거했다. 양쪽 패널을 접어도 가운데의 문항 탭은 사용할 수 있다. 휴대폰에서는 문항 선택을 기존 버전 / 작성 / 채팅 줄에 함께 두어 어느 작업 영역에서도 접근한다. 최신 분기·병합 규칙은 [스냅샷·분기·병합](07-snapshots-branch-merge.md)에 정리했다.

## 이력의 단위

- 각 문항은 자체 초안, 스냅샷, 부모 관계, 번호, 비교 선택과 피드백 대화를 가진다. 일반 스냅샷의 부모는 하나이고 병합 스냅샷은 선택한 두 기록을 부모로 가진다. 한 문항의 스냅샷·분기·병합·AI 적용은 그 문항에만 영향을 준다.
- Q1의 v2와 Q2의 v2는 같은 기록이 아니다. 지원 건·문항·답변 버전 식별자로 구분한다. 화면의 v번호는 문항 안에서 읽는 번호다.
- AI 요청은 문항과 당시 원문에 연결된다. 다른 문항을 작성하는 중 응답이 와도 요청한 문항의 대화에 남고, 적용 시 해당 문항에만 새 버전이 생긴다.
- 문항을 바꿔도 미저장 본문, 입력 중인 채팅 메시지, 비교 선택이 유지된다. 미저장 변경이 있는 상태에서 과거 버전으로 작성하려고 하면 먼저 저장하도록 안내한다.
- 제출본은 ‘Q1의 선택 버전 + Q2의 선택 버전 + …’을 당시 문항·조건·내용과 함께 고정한 묶음이다. 제출 이후 개별 문항을 수정해도 바뀌지 않아야 한다. 제출본 UI는 이번 미리보기 범위 밖이다.

초기 예시는 Q1에 v1·v2·다른 도입의 v2-A, Q2에는 v1만 두었다. 두 문항의 이력이 다르다는 점을 직접 확인할 수 있다. 문항 선택 위치만 옮겼으며 문항별 데이터 구조는 유지한다.

## 구현과 구분

이번 변경은 와이어프레임의 로컬 상태 구조와 기획 기준 변경이다. Docsa 원본 코드와 실제 DB/API는 변경하지 않았다. 문항 ID·답변 버전 ID를 받는 MCP 도구 표기는 설계 예시이며 구현된 API 계약이 아니다. 실제 서버 구현에서는 문항 소유권과 버전의 문항 소속까지 검사해야 한다.

초안과 예시 응답은 새로고침 시 초기화된다. 실제 AI·MCP 연동, 영속 저장과 제출본 조립은 구현하지 않았다. 여러 문항을 동시에 일괄 복원하는 기능은 이번 화면에 포함하지 않는다.

## 확인할 동작

Q1에서 글을 고쳐 저장한 뒤 Q2로 이동해 그래프·답변이 그대로인지 확인한다. Q2에서 AI 수정안을 적용한 뒤 Q1 이력이 늘지 않았는지 확인한다. 양쪽 문항에서 피드백을 요청해 응답이 원래 문항에 도착하는지 확인한다. 과거 버전에서 작성·저장해도 다른 문항은 유지되어야 한다.

검증 기록과 화면 이미지는 프로젝트 `_workspace/2026-11-01-question-versions/`에 보관한다.

브라우저 확인 결과: 문항 전환 시 초안·메시지·그래프 보존, 문항별 저장 번호·복원·AI 적용의 독립성, 동시 요청 응답의 문항 소속, 오래된 후보·중복 적용 차단, 모바일 전환을 통과했다. 1200·1024·736·375·320px에서 가로 넘침과 실행 오류가 없었다. 실제 서버 동작을 확인한 결과는 아니다.

## 색상 보완: 2026-11-01

사용자는 섹션 배경은 TIO 참고처럼 무채색으로 두고, 기존 파란 팔레트는 포인트에만 쓰도록 요청했다. 상단·편집면은 흰색, 좌측은 옅은 회색, 채팅은 더 밝은 회색으로 구분한다. 일반 그래프 선과 노드는 회색이며 선택 문항·선택 버전·현재 노드·저장/전송 버튼·변경 문구에 파란색을 사용한다. 레이아웃·문항별 버전 로직은 바꾸지 않았다. 브라우저에서 중립 섹션 색상과 포인트 색, 비교 강조, 채팅 응답 표시와 모바일 배치를 확인했다. 기록은 `_workspace/2026-11-01-neutral-surfaces/`에 있다.

## 작성에 집중하기: 2026-11-01

사용자 요청에 따라 작성 화면 위의 마감·지원 상태 바를 제거했다. 회사명 왼쪽에 ‘← 지원 현황’을 표시해 현황 목록·캘린더로 이동한다. 지원 상태 변경은 현황 목록에서 한다. 작성 화면부터 확인하면서 왕복할 때는 `wireframes/application-editor.html`을 사용한다.

접기 버튼은 각 패널 상단의 작성 영역 쪽 모서리에 둔다. 좌측은 오른쪽 위, 우측 채팅은 왼쪽 위의 방향 아이콘이다. 접으면 가장자리에 좁은 영역과 펼치기 버튼을 남긴다. 툴팁과 접근성 이름으로 대상을 알리고, 키보드로 접은 뒤에도 해당 버튼에 초점을 유지한다. 상단 헤더에는 접기 버튼을 두지 않는다.

좌측 버전 그래프와 우측 AI 대화는 독립적으로 접고 펼친다. 둘 다 접으면 가장자리의 펼치기 버튼을 제외한 폭을 작성·비교에 사용한다. 문항별 본문과 메시지 초안, 도착한 응답은 유지된다. 피드백을 명시적으로 요청하면 채팅을 열고, 이후 사용자가 접었을 때 응답 도착만으로 강제로 다시 열지 않는다.

휴대폰에서는 버전 / 작성 / 채팅 탭을 사용하고 데스크톱 접기 버튼은 표시하지 않는다. 지원 건마다 접기 상태를 미리보기 안에서 유지하며, 다른 지원 건이나 새로고침에는 전파하지 않는다. 실제 사용자 설정 영속 저장은 구현하지 않았다.

브라우저에서 패널 안의 버튼 위치·아이콘·가장자리 펼치기, 접근성 상태와 초점 유지, 목록·캘린더·작성 화면 왕복, 지원 건별 접기 상태와 본문·채팅 초안·응답 보존을 확인했다. 1200·1024·736px의 네 접기 조합과 모바일 영역 전환도 확인했다. 기록은 `_workspace/2026-11-01-collapsible-editor/panel-navigation-verification.json`에 있다.

## 작성·채팅 입력 배치 보완: 2026-11-01

글자 수는 문항 제목 옆에 표시하며 입력하거나 문항을 바꿀 때 갱신한다. 작성 영역 아래의 글자 수·피드백 요청 줄과 구분선을 제거하고 본문이 그 공간을 사용하도록 했다. 비교 화면의 두 버전 글자 수와 적용 동작은 유지한다.

‘피드백 요청’은 채팅 입력창 바로 위에 둔다. 별도 보내기 버튼은 두지 않고 Enter로 전송, Shift+Enter로 줄바꿈한다. 한글 조합 중 Enter, 빈 메시지, 응답 대기 중 중복 요청은 전송하지 않는다. 휴대폰 키보드에도 전송 동작을 표시한다.

브라우저에서 위치·실시간 글자 수·문항별 분리, 키보드 전송과 줄바꿈·조합 중 전송 방지, 응답 대기 중 초안 보존, 피드백 비교·적용, 1200·1024·736·375·320px 배치를 확인했다. 검증 기록은 `_workspace/2026-11-01-collapsible-editor/compact-editor-verification.json`이다. 기존 패널 접기와 지원 현황 왕복 검증도 다시 통과했다.
