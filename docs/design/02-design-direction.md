# 단순한 편집기와 피드백 대화

2026-10-31 · 이전 검토 기록. 최신 배치는 [그래프 · 작성 · AI 채팅](03-three-column-workspace.md)을 따른다.

## 바뀐 방향

사용자는 한 화면에 비교·버전 목록·수정 후보·제출본·설명문이 몰려 복잡하고 AI가 만든 화면처럼 보인다고 지적했다. 이전 자소서와 단순 비교하는 페이지를 분리하고, AI 피드백은 채팅방에서 요청한 뒤 응답의 수정안을 비교하기를 원했다.

현재 화면을 다음 세 작업으로 분리했다.

1. 작성: 문항, 본문, 글자 수, 저장. ‘피드백 요청’으로 해당 문항의 대화를 시작한다.
2. 버전 비교: 이전·이후 선택과 두 본문. 원문은 그대로, 이후 글에서 추가·변경 부분만 파란색으로 표시한다. 채팅과 버전 목록을 함께 펼치지 않는다.
3. 피드백 대화: 요청과 답변을 대화로 주고받고, 답변에 수정안이 있을 때 ‘비교하기’로 이동한다. 원문과 수정안을 확인한 뒤 적용하면 새 버전으로 저장된다.

화면 전체를 감싸는 카드, 반복 배지·범례·패널 설명, 문단별 화살표·회색 빈 상자, 공고 요약 사이드바, 긴 버튼 문구를 제거했다. 본문과 화면 제목·작업 버튼의 위계를 간격과 글자 크기로 구분한다. 색은 활성 문항과 변경 표현에 제한하고 그라데이션·발광·장식 아이콘·인위적인 통계는 사용하지 않는다.

참고 이미지에서 문항 중심 편집과 채팅의 관계를 가져왔으며, 다른 기능 탭이나 로고·개인정보·채용 문구를 복제하지 않았다. 이번에는 피드백 대화도 별도 화면으로 분리하는 안으로 제안한다. 이것이 최종 디자인으로 승인된 것은 아니다.

## 조사한 내용과 적용

‘AI스러운 디자인’은 객관적인 판별 기준이 아니다. 아래 글의 의견을 제품 사용성 기준과 함께 참고했다. 특정 색·폰트·둥근 모서리가 있다는 이유로 AI 제작이라고 판단하지 않는다.

- [Joshua Snoddy: Why do AI-generated websites all look the same?](https://www.joshuasnoddy.com/blog/why-ai-websites-look-the-same/)는 보라색 그라데이션, 유리 카드, 반복되는 중앙 정렬 구성, 기본 컴포넌트의 무비판적 재사용을 비평한다. 디자이너의 관찰이며 학습 데이터나 사용자 신뢰에 관한 인과 주장을 이 작업에서 검증한 것은 아니다. 여기서는 장식과 반복 카드 구성을 줄이는 참고로만 쓴다.
- [InterfaceKit: What makes a website look AI-generated?](https://blog.interfacekit.io/what-makes-a-website-look-ai-generated)는 제품에 특화되지 않은 구조와 문구, 목적 없는 장식, 불완전한 상태를 주요 문제로 본다. 여기서는 ‘작성·과거 비교·응답 비교’라는 실제 작업에 맞게 화면을 분리하는 판단에 활용했다.
- [NN/g: Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)는 필요한 정보를 가리는 불필요한 요소를 줄이되 작업에 필요한 기능은 남기도록 설명한다. 본문 주변의 설명을 제거하고 저장, 문항 선택, 비교, 피드백 요청은 유지했다.

## 피드백 기능의 범위

채팅과 응답은 흐름 검토를 위한 로컬 예시다. 실제 AI가 사용자가 보낸 자유로운 질문을 이해해 답하는 구현이 아니다. 요청 당시 문항과 전체 답변을 복사해 보관하고, 예시 답변과 수정안을 보여 준다. 응답은 요청한 문항의 대화에만 남는다. 요청 후 본문이 바뀌면 해당 후보의 적용을 막는다. 적용 여부를 기록해 중복 적용을 막고, 두 문항의 대화는 분리한다.

내부 채팅은 사용자가 원하는 제품 경험으로 반영하되, MCP·일반 API·SIWC 중 실제 호출 경로는 여전히 기술 검증과 비용 결정을 거쳐야 한다. 내장 채팅이 구현됐거나 사용자 구독 연동이 승인됐다는 뜻은 아니다. 기존 기획의 외부 ChatGPT MCP 경로와의 관계는 다음 기획 검토에서 확정한다.

제출본·공고·캘린더 기능을 삭제하는 결정은 아니다. 이번 편집 화면과 비교 화면에서 이 기능을 다루지 않는다. 문단 매칭 엔진·스크롤 동기화는 이번 단순 비교안에 추가하지 않고 전체 본문 두 개를 읽게 한다. 화면 배치 확인용이며 영속 저장·인증·네트워크·실제 AI 호출은 없다.

## 검토할 순서

작성 → 버전 비교 → 작성으로 복귀 → 피드백 요청 → 채팅 응답 → 비교하기 → 수정안 적용.

소재를 바꾸거나 문장을 보완하는 후속 요청도 입력할 수 있지만 예시 응답을 반환한다. 실제 모델의 품질을 평가하는 도구가 아니다. 브라우저 동작과 화면 확인 기록은 프로젝트 `_workspace/2026-10-31-simple-editor/`에 남긴다.

## 확인 결과

브라우저에서 작성·버전 비교·피드백 화면 분리, 요청→응답→비교→새 버전 적용, 중복 적용 방지, 요청 후 원문 변경 시 적용 차단, 문항별 대화 분리와 요청 대기 중 문항 전환을 확인했다. 세 화면 모두 1024·736·375·320px에서 가로 넘침이 없었고 실행 오류가 없었다. 밝은 화면과 어두운 화면을 검토했다. 이는 예시의 동작 확인이며 실제 모델 품질·계정 연결·영속 저장 검증은 아니다.
