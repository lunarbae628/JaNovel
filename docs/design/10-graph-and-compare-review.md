## 비교 화면

비교 하단의 구분선·글자 수·분기 버튼 줄을 제거했다. ‘여기서 분기하기’는 이전 버전 선택 옆으로 옮겨 해당 원문을 출발점으로 삼는다는 관계를 드러낸다. 글자 수 변화는 문항 제목 바로 옆에 둔다. 하단 버튼을 위해 남겨 둔 작업 줄 없이 두 본문을 읽는다. 두 본문이 짧으면 남는 편집 공간 자체를 장식이나 설명으로 채우지는 않는다.

변경 화면: [버전 비교](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=5-647).

## Docsa에서 확인한 방식

원본 프론트엔드는 읽기만 했다.

- `DocumentGraph.tsx`: React Flow, 갈래 전환, 그래프 확대·이동과 화면 맞춤을 제공한다. 노드 직접 드래그와 연결 편집은 막는다.
- `useGraphData.ts`: 갈래별 가로 위치를 정하고 부모 연결 관계의 깊이에 따라 세로 위치를 계산한다. 병합 대상과 시작점으로부터 병합 결과에 필요한 연결선을 보완한다.
- `graphUtils.ts`: 갈래 간격 280, 노드 폭 220·높이 112, 세로 간격 190을 사용한다.
- `TimelineEdge.tsx`: 위·아래 연결점 사이에 곡선을 그린다.

Docsa의 전체 화면 맞춤만으로 많은 기록의 가독성이 보장되는 것은 아니다. 화면에 전부 맞추려고 계속 축소하면 글자가 작아질 수 있다. 이 검토는 코드 구조 확인이며 실제 대규모 그래프의 성능·사용성을 측정한 결과는 아니다.

## 기존 시안의 문제와 수정

이전 그래프는 갈래마다 항목 전체를 오른쪽으로 28px씩 밀었다. 그래프 폭이 176px이면 항목 폭은 `176 - 28 × 갈래 위치`가 되므로 갈래 위치가 5일 때는 36px, 6일 때는 8px만 남는다. 이름과 번호를 유지하기 어렵다.

수정한 사이드 그래프는 연결선 영역과 이름 영역을 분리한다. 이름은 항상 x=52, 폭 124px를 사용해 들여쓰기 누적으로 줄어들지 않는다. 현재 갈래와 연결된 병합 이력을 간략히 보이고 ‘전체 보기’에서 전체 갈래를 확인하는 방향이다. 이번 간략 예시는 관련된 두 갈래의 스냅샷 6개와 작업 중 답변 1개다. 많은 기록을 어디서 끊고 이전 기록을 불러올지는 후속 구현에서 다룬다.

복잡한 관계는 넓은 그래프에서 Docsa처럼 갈래별 열과 부모 관계를 함께 보여 준다. 기록의 이름을 계속 줄이거나 모든 기록을 자동으로 작은 글씨로 축소하는 방식에 의존하지 않는다. 넓은 그래프의 기본 설계는 확대·이동이며, 이번 Figma는 배치와 컨트롤 모양을 보여 주는 디자인 상태다. 실제 확대·축소 기능을 구현한 것은 아니다.

## 병합 예시

[전체 그래프 · 병합 예시](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=15-342)에 3개 갈래와 스냅샷 8개·작업 중 답변 1개를 배치했다.

- 기본: v1 → v2 → v3
- 직무 강조: v1 → v2-A → v3-A
- 경험 강조: v1 → v2-B → v3-B
- 병합: v3 + v3-A → v4 → 작업 중 답변

v4에는 두 부모에서 들어오는 연결선을 별도로 그렸으며, 경험 강조 갈래는 병합되지 않은 채 유지한다. 좁은 그래프와 전체 그래프 모두 같은 병합 부모를 보여 준다. 기록·연결선·문구는 편집 가능한 레이어다.

## 확인 결과와 한계

Figma 변경 결과에서 하단 작업 줄이 제거됐고 분기 버튼이 이전 버전 선택 영역의 폭 안에 배치됐음을 확인했다. 사이드 이름 열은 21개 항목 모두 같은 x좌표·폭을 반환했다. 전체 예시 그래프의 계산된 경계는 944 × 584px이며 1160 × 640px 뷰포트에 들어간다. v4의 부모는 v3·v3-A 두 개다.

예시용 배치 함수에 33개 노드와 여러 갈래·두 병합을 넣어 노드 사각형이 겹치지 않고 부모가 자식보다 위에 오며 순환 입력을 거부하는지 확인했다. 이 조건에서의 배치 검사이며 모든 그래프의 연결선 교차·복잡도나 제품 성능을 보장하지 않는다. 현재 예시 함수와 Docsa의 실제 배치 엔진은 서로 다르다.

마지막 캡처 요청에서 Figma Starter MCP 호출 한도에 도달했다. 변경은 저장됐지만 이번 수정본의 최종 렌더링 검수는 완료하지 못했다. 이전 버전의 캡처 검수를 이번 결과의 검증으로 대신하지 않는다. 캔버스 변경 결과는 로컬 `_workspace/2026-11-06-figma/merge-graph-result.json`에 남긴다.

## 2026-11-07 · 주변 기록과 사이드바 확장으로 방향 변경

사용자 요청: 좁은 사이드바에는 선택한 노드 주변만 노출하고, 원하면 전체 그래프를 확인한다. 전체 보기는 별도 모달 대신 기존 그래프 사이드바를 넓히는 방식으로 한다. 위의 전체 그래프 모달 예시는 이전 시안이며 교체 대상이다. 이 절은 변경 요구사항 기록이며 Figma 반영 완료를 뜻하지 않는다.

세부 동작 제안:

- 기본 화면은 선택한 스냅샷과 바로 연결된 부모·자식만 보여 준다. 작업 중 답변을 선택하면 출발 스냅샷과 그 부모까지 보여 맥락을 남긴다.
- 병합 스냅샷은 두 부모와 두 연결선을 함께 보여 준다. 화면 밖에서 이어지는 이력은 생략 표시로 구분하며, 숨긴 구간을 직접 연결된 관계처럼 그리지 않는다.
- 보이는 범위 밖의 기록은 ‘이전 기록’·‘다른 갈래’ 등의 짧은 진입점과 개수로 표시한다. 상세 목록이나 전체 그래프로 이동할 수 있다.
- ‘전체 보기’는 같은 문항의 그래프 사이드바를 확장한다. 많은 갈래를 화면에 맞추려고 계속 축소하지 않고 이동·확대·축소로 탐색한다. 채팅 패널이나 작성 영역 위를 덮는 모달은 사용하지 않는다.
- 좁은 화면으로 돌아오면 선택 노드와 작성·비교 상태를 유지한다. 노드 선택은 탐색 동작이며 작성 중인 텍스트를 덮어쓰지 않는다.

시안 검수에는 일반 스냅샷·두 부모 병합·분기 직후·작업 중 답변을 포함한다. 숨긴 노드가 있어도 연결 관계를 오해하지 않는지, 전체 보기 왕복 후 선택과 작성 상태가 유지되는지 확인한다. 정확한 노드 개수 제한과 확장 폭은 후속 시안에서 검토할 설계값이다.

### 같은 날 Figma 반영과 확인

Talk to Figma 연결을 통해 기존 파일을 수정했다. 사용자 추가 요청에 따라 전체 보기에서도 카드 대신 작은 원형 노드와 옆의 이름을 사용했다.

- 작성·비교 화면의 좁은 그래프는 v3·v3-A·v4·작성 중 답변의 네 노드와 ‘숨긴 기록 · 5개’를 표시한다. v4에는 v3·v3-A 두 부모의 연결을 남겼다. 스냅샷 대화상자 배경의 그래프에도 같은 구성을 적용했다.
- 기존 전체 보기 모달과 배경 가림막을 제거했다. 같은 목적지 프레임 `15:342`를 ‘전체 그래프 · 사이드바 확장’으로 바꿨다. 사이드바 520px, 비교 영역 558px, 채팅 360px에 구분선 두 개를 배치해 전체 1440px 안에 들어간다. 기본 사이드바 폭은 208px이다.
- 전체 그래프에는 스냅샷 8개와 작성 중 답변 1개, 세 갈래를 표시한다. 병합 노드는 12px, 나머지 원형 노드는 10px다. 이름 열은 124px를 유지한다. 갈래를 잇는 곡선이 이름 뒤에 가려지지 않도록 글자 사이의 빈 구간으로 연결을 옮겼다.
- 비교 대상은 v3·v4로 맞췄다. 넓은 그래프 상태에서는 비교 대상과 분기 버튼을 좁은 본문 폭에 맞게 줄여 배치했다. 분기 버튼은 원문 선택 옆에 남긴다.
- ‘전체 보기’의 기존 목적지 프레임과 ‘주변 보기’의 뒤로 가기 동작은 유지했다. 프로토타입 클릭 왕복 자체는 이번 검수에서 실행하지 않았다.

작성·비교·사이드바 확장 화면을 직접 내보내 확인했다. 최종 비교·확장 화면 캡처에서 본문·채팅이 패널 경계를 침범하지 않고 노드 이름과 병합선이 읽히는 것을 확인했다. 세 화면의 텍스트는 모두 Noto Sans KR이며 전체 UI를 대체하는 이미지 채우기는 없다. 좁은 그래프는 원 4개·이름 인스턴스 4개, 전체 그래프는 각각 9개다. 스냅샷 대화상자의 배경은 별도 캡처로 검수하지 않았다.
