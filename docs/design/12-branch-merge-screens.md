# 분기·병합 디자인

후속 사용자 요청으로 아래 문단 선택 방식은 [Docsa 기준 키워드 비교·3열 병합](13-docsa-keyword-compare-merge.md)으로 교체했다. `37:441`이 현재 키워드 병합 화면이며 별도 결과 확인 프레임 `37:569`는 제거했다. 아래는 교체 전 작업 기록이다.

[Figma 병합 선택 화면](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=37-441).

기존 문항별 주변 그래프와 회사 헤더·채팅 영역을 재사용했다. 병합 후보를 검토하는 동안 기존 그래프와 초안을 보존하고, 확정 시 두 부모를 가진 새 스냅샷을 만드는 흐름이다. 병합 스냅샷의 이름·설명은 기존 스냅샷 입력창 구성을 재사용한다. 원래 기록을 바꾸는 동작으로 표현하지 않는다.

이번 예시는 두 문단이 같고 두 번째 문단만 다른 상황이다. 같은 문단은 결과에 그대로 포함하며 선택이 필요한 문단에만 선택 도구를 둔다. 결과는 별도 상태에서 충분한 폭으로 읽고 직접 수정한다. 자동 충돌 해결이나 공통 조상 기반 병합이 아니다.

## 확인한 것과 남은 것

세 상태를 Figma에서 내보내 확인했다. 이름·설명과 버튼이 입력창 안에 들어가고, 병합의 선택·결과 도구가 가운데 영역에 있으며 채팅 폭을 침범하지 않는다. 비교 화면에서 물려받은 긴 구분선을 실제 선택 영역 높이로 줄였다. 세 화면의 텍스트는 모두 Noto Sans KR, 이미지 채우기는 0개다.

Figma는 편집 가능한 디자인 상태다. 새 버튼의 화면 간 연결을 모두 다시 지정하거나 클릭 왕복을 검증하지 않았다. 일부 복제된 버튼은 기존 화면으로 연결돼 있으므로 완성된 클릭 프로토타입으로 안내하지 않는다. 새로운 분기 직후·병합 확정 직후의 개별 그래프 상태와 미선택·다수 변경 문단·취소·작성본 변경 상태는 후속 디자인 범위다. 복원 화면도 이번에 추가하지 않았다.

## 동작을 확인할 로컬 시안

기존 HTML 시안에서 분기·병합 검토를 바로 시작하는 진입점을 생성했다. 새 기능 구현이 아니라 기존 시안의 상호작용을 재사용한 검토용 화면이다.

- `docs/design/wireframes/branch-review.html`
- `docs/design/wireframes/merge-review.html`
- 재생성: `python3 scripts/wireframes/build-versioning-review.py`

분기 이름·설명 입력 → 출발 기록을 유지한 새 갈래 → 수정 후 스냅샷, 병합 문단 선택 → 직접 수정 → 이름 입력 → 두 부모 연결을 브라우저에서 확인했다. 1024·736·320px에서 가로 넘침과 실행 오류가 없었다. 기존 HTML 그래프·비교 배치 전체를 최신 Figma와 동기화한 것은 아니다. 가짜 AI 응답과 메모리 상태이며 영속 저장·실제 AI·MCP는 연결되지 않았다.

로컬 검사 결과와 화면은 `_workspace/2026-11-06-figma/versioning-review-verification.json`과 같은 폴더의 캡처에 있다. 새 Figma 노드·검사 수치는 `versioning-screens-result.json`에 기록한다.
