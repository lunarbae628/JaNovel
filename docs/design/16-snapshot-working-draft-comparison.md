# 스냅샷과 작성 중 초안 비교

2026-11-08 · 노드 선택 후 본문 내역 · 디자인 시연

## 확정한 조작

노드를 누르면 팝업을 거치지 않고 가운데 본문 영역에 좌우 비교가 열린다.

- 왼쪽은 누른 스냅샷의 본문이다. 오른쪽 대상을 바꿔도 왼쪽 기록은 고정한다.
- 오른쪽 기본 대상은 해당 문항의 ‘작성 중’ 본문이다. 대상 선택창에서 작성 중 초안 또는 같은 문항의 다른 스냅샷을 고른다.
- ‘작성 중’은 스냅샷을 남기지 않은 편집 내용도 포함한다. 비교를 위해 스냅샷을 자동 생성하지 않는다.
- 선택창에서 다른 스냅샷을 본 뒤 다시 ‘작성 중’으로 돌아갈 수 있다. 비교 대상 변경만으로 초안을 복원하거나 갈래를 바꾸지 않는다.
- 문항 옆 글자 수는 왼쪽과 오른쪽의 글자 수를 함께 표시한다. 공통 내용은 그대로 두고 바뀐 단어·구절만 무채색과 파랑으로 강조한다.
- 병합·분기와 작성으로 돌아가기는 가운데 도구 줄에서 실행한다. 좌측 그래프와 우측 AI 채팅의 배치는 유지한다.
- 2026-11-09 사용자 지시에 따라 본문 내역·비교 화면의 ‘이 기록으로 복원’ 버튼을 제거했다.

## 검증과 구현 경계

디자인에서는 현재 작성 화면의 본문을 읽어 ‘작성 중’ 예시로 사용한다. 본문과 선택창은 편집 가능한 Figma 레이어로 구성한다. 전환 설정을 다시 읽고 선택한 왼쪽 기록 유지, 대상 변경, 작성 중 초안으로 돌아오기, 노드의 직접 이동을 검사한다. 생성 소스는 `scripts/figma/compare-working-draft.mjs`, 검사 소스는 `scripts/figma/verify-working-comparison.mjs`다. 관련 검사 기록은 `_workspace/2026-11-08-interactions/`에 둔다.

실제 서비스에서는 해당 문항·갈래의 현재 편집 값을 비교 대상으로 사용해야 한다. 서버의 과거 스냅샷이나 마지막 저장 값만 읽으면 아직 반영하지 않은 편집이 빠질 수 있다. 비교 요청과 스냅샷 생성은 구분한다.

현재 Figma는 유한한 예시 상태를 이동하는 프로토타입이다. 실제 입력과 함께 비교 내용이 갱신되는 동작, 편집 보관, API 호출, 병합 저장은 제품 구현 범위다. 기존 Figma의 동기화 대기 표시는 별도로 확인해야 한다.

## 이번 검사 결과

선택한 기록 화면 12개와 대상 전환·복귀 경로 64개를 저장된 Figma 전환 설정에서 검사했다. 작성 중 초안이 기본 대상이고 비교 자체가 스냅샷을 생성하지 않는 상태로 연결됨을 확인했다. 전체 클릭 설정의 읽기 검사와 대표 경로 검사도 통과했다. 포인터로 모든 조합을 직접 클릭한 결과나 제품의 실제 저장 검증은 아니다.
