# 로그인·회원가입, 패널 너비와 브랜치별 작업장

2026-11-10. 실제 제품 인증 구현 전의 편집 가능한 Figma 화면과 로컬 동작 시안이다.

## 디자인 기준과 범위

- UI UX Pro Max의 폼 레이블·비밀번호 관리자·키보드 접근 지침을 적용한다. 제안된 랜딩 페이지 영상·새 색상·새 서체는 기존 제품과 맞지 않아 적용하지 않는다. 무채색, Noto Sans KR, French Blue를 유지한다.
- 로그인은 이메일·비밀번호를 사용한다. 가입은 이메일 인증과 이름·비밀번호 설정의 두 단계로 나눈다. Docsa의 기존 이메일 인증 API와 가입 필드를 기준으로 한 시안이며, 인증 코드와 비밀번호 정책은 실제 구현에서 서버 계약을 재확인한다.
- 별도 AI 계정 연결은 서비스 로그인과 구분한다. 후속 요청으로 Google·카카오 OAuth 버튼을 추가한다. 실제 제공자 인증은 연결하지 않는다.
- 동작 시안은 실제 계정을 만들거나 이메일을 보내지 않는다. 인증코드·완료 화면은 명시적으로 예시임을 표시한다.

## 패널 너비

- 그래프·채팅 경계의 세로 핸들을 드래그한다. 좌우 방향키로도 조절하고 Home/End로 가능한 최소·최대 너비로 이동한다.
- 기본은 왼쪽 240px, 오른쪽 320px. 작업 화면에서 가운데 최소 420px를 확보하고 왼쪽 184–420px, 오른쪽 264–480px 범위와 실제 창 너비를 함께 제한한다.
- 접기와 전체 보기는 유지한다. 창이 좁아질 때는 패널을 겹쳐 쌓지 않고 닫거나 다시 펼칠 수 있게 한다. 별도의 모바일 작성 최적화는 후속 범위다.
- Figma에는 핸들과 대표 너비 상태를 표현한다. 자유로운 픽셀 단위 드래그는 브라우저 시안에서 검증한다.

## 브랜치별 작성 중

- Docsa `Branch`는 `Save`와 일대일 관계다. `BranchGraphDto.saveId`는 브랜치의 현재 작업장을 뜻한다. `useGraphData.ts`는 `saveId`가 있는 각 브랜치에 `save-{id}` 임시 노드를 만들며, `DocumentGraph.tsx`는 작업장을 비교 대상으로 지원한다.
- 따라서 문항 전체에 하나의 작성 중 노드를 두는 시안을 수정한다. 기본·다른 도입·사례 중심 세 브랜치의 마지막 스냅샷 아래에 각각 작성 중을 둔다.
- 브랜치에 저장된 스냅샷이 없으면 분기 시작점에서 작업장으로 이어진다. 병합해도 원본 브랜치를 자동 삭제·종료하지 않는다.
- 작업장 ID와 브랜치 ID를 구분한다. 제목은 ‘작성 중 · 브랜치 이름’, 색은 그 브랜치 색으로 유지한다. 다른 브랜치로 전환해도 작성 중 텍스트를 덮어쓰지 않는다.
- 로컬 시안에서 세 초안은 별도 편집 상태를 가지며, 선택한 스냅샷과 비교할 작업장도 고를 수 있다. 새로고침 뒤 영구 보존과 서버 연동은 아직 없다.

## 완료 확인

로그인/가입 단계 간 이동과 입력 오류, 양쪽 경계 드래그·키보드 조절·최소 본문 너비, 세 작업장 노드와 부모 관계, 브랜치 간 초안 편집 분리와 비교 대상 선택을 확인한다. 원본 Docsa 저장소는 읽기만 한다.

## 확인한 결과

- Figma 인증 화면 5개에서 화면 밖으로 넘치는 요소가 없고, 주요 이동을 연결했다. 로그인과 가입 시작 화면에는 Google·카카오 버튼도 있다.
- 브라우저에서 잘못된 인증번호·비밀번호 불일치 안내와 가입 단계 전환을 확인했다.
- 양쪽 패널을 각각 80px 드래그하고 방향키로 8px씩 조절했다. 가운데 본문 공간이 유지되는 것을 확인했다.
- 브랜치 A를 편집한 뒤 B로 갔다 돌아와도 A 내용이 유지됐다. 각 작업장을 비교 대상으로 선택할 수 있다. 서버·새로고침 뒤 영구 저장은 미연결이다.
- 지도형 패널 99개 중 기록이 있는 94개에 브랜치별 작업장을 반영했다. 비어 있는 5개는 빈 상태로 남겼다.
