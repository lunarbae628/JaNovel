# 지원 현황: 목록과 캘린더

2026-11-01 · 흐름 검토용 미리보기 · 제품 구현 전

## 사용자와 합의한 작업

작성 페이지는 1차안으로 두고, 회사·직무·마감일·진행 상태를 확인하는 지원 현황 화면을 만든다. 목록과 캘린더를 전환하고 지원 건을 누르면 기존 작성 화면으로 이동한다. 무채색 섹션과 파란 포인트, 불필요한 설명·카드·통계 최소화 원칙을 유지한다.

현황에서 시작하는 미리보기는 `wireframes/application-overview.html`, 작성 화면에서 시작하는 미리보기는 `wireframes/application-editor.html`이다. 기존 `wireframes/essay-workbench.html` 경로도 같은 작성 진입점으로 제공한다. 각 진입점에 같은 화면을 합성해 왕복 동선을 확인할 수 있게 했다. 실제 애플리케이션 라우팅 구현은 아니다.

## 목록

회사와 직무, 마감 날짜·시간, 상태, 다음 전형 일정을 한 행에 표시한다. 상태는 관심·작성 중·제출·전형 진행·종료이며 직접 변경한다. 상태 필터는 목록과 캘린더에 함께 적용된다. 해당 상태가 없으면 빈 상태를 보여 준다. 마감이 지났다는 이유로 지원 상태를 자동 변경하지 않는다.

회사를 누르면 해당 지원 건의 작성 화면이 열린다. 작성 화면에서는 마감·지원 상태 바를 제거하고, 회사명 왼쪽에 ‘← 지원 현황’을 둔다. 마감과 상태 관리는 지원 현황에서 한다. 지원 건마다 미리보기 안의 문항별 초안·그래프·AI 대화를 별도로 유지한다. 목록으로 돌아가거나 다른 지원 건을 방문해도 유지되지만 새로고침 시 초기화된다. 작성 화면의 문항과 본문은 모두 예시다.

모바일 목록은 회사·직무, 마감, 상태에 집중하고 다음 일정 열을 숨긴다. 전형 일정은 캘린더에서 확인한다. 이 모바일 우선순위는 이번 초안의 제안이다.

## 캘린더

월간 달력에서 마감·면접·과제·기타를 날짜에 배치한다. 이전·다음 달로 이동하고 날짜를 선택하면 해당 날짜의 모든 일정을 옆에서 확인한다. 모바일에서는 일정 상세를 달력 아래에 배치한다. 날짜 칸에는 최대 두 일정을 축약 표시하고 추가 건수를 알린다. 일정의 종류를 글자로 표시해 색에만 의존하지 않는다.

날짜만 있는 마감·일정은 임의의 시각을 붙이지 않고 ‘시간 미정’으로 보인다. 마감일이 없는 공고는 ‘마감일 미확인’, 상시채용은 별도 ‘상시채용’ 구역에서 찾는다. 날짜 칸에 임의로 넣지 않는다. 공개용 날짜 계산과 실시간 D-day를 제공하는 구현은 아니며 초기 예시는 2026년 11월 기준이다.

일정 추가는 지원 건·종류·일정명·날짜와 선택적인 시간을 받는다. 이름과 날짜가 없으면 입력 안내를 표시한다. 저장하면 해당 달과 날짜를 선택하고 목록의 다음 일정에도 반영한다. 실제 마감일 입력·변경은 후속 공고 등록 화면에서 다룰 항목으로 남겼다. 이번 일정 추가는 면접·과제·기타를 대상으로 한다.

시간 없는 일정과 마감일을 처리해야 하므로, 시작·종료 시각을 요구하는 시각화 기본 캘린더 대신 제품 전용 월간 격자를 사용했다. 외부 일정 서비스와 동기화하거나 알림을 전송하지 않는다.

## 범위

6개 회사·직무·공고·마감은 모두 가상의 예시다. 실제 채용 정보나 접수 여부를 확인한 자료가 아니다. 회사별 작성 화면도 같은 구조의 예시 문항에서 독립적으로 시작한다. 실데이터 연결, 계정·DB·영속 저장, 외부 공고 수집·등록, 실제 AI·MCP, 실제 제출은 구현하지 않았다.

‘+ 공고 등록’에서 [공고 등록·문항 확인 화면](06-posting-registration.md)으로 이동한다. 새 공고의 문항과 채용 절차를 등록해 작성 화면과 상태 선택에 반영하는 예시 동작을 연결했다. 실제 자동 추출은 미연결이다. 종료 결과, 일정 수정·삭제, 모든 일정이 과거일 때의 정리 정책 등은 후속 상세 설계 대상이다.

## 확인

브라우저에서 목록 상태 변경·필터·빈 상태, 월 이동·날짜 선택·일정 상세, 날짜/시각 미확인과 상시채용의 분리, 일정 입력 검증·저장, 목록과 달력의 데이터 일치, 회사별 작성 화면 왕복과 초안·그래프 분리를 확인했다. 입력한 일정명은 HTML로 해석하지 않고 텍스트로 표시한다.

목록과 캘린더를 각각 1024·736·375·320px에서 확인했고 가로 넘침과 실행 오류가 없었다. 화면과 검증 기록은 `_workspace/2026-11-01-application-overview/`에 있다. 이는 로컬 예시 동작 확인이며 실제 운영이나 실제 지원에 대한 검증은 아니다.

## 작성 화면과의 이동 보완

작성 화면 왼쪽 위 ‘← 지원 현황’으로 현황 목록·캘린더에 이동한다. 목록의 회사를 선택하면 해당 작성 화면으로 돌아가며 문항별 초안·버전·대화와 좌우 패널 접기 상태가 유지된다. 새로고침 후의 영속 저장은 포함하지 않는다.

`wireframes/application-overview.html`은 현황 목록에서, `wireframes/application-editor.html`과 `wireframes/essay-workbench.html`은 작성 화면에서 시작한다. 모든 미리보기는 같은 화면과 이동 동작을 포함한다. 조합용 작성 원본은 `scripts/wireframes/editor-source.html`에서 관리한다. 2026-11-02에 기존 작성 경로에서 돌아가기 버튼이 없던 문제를 재현하고, 해당 경로에도 통합 화면을 제공하도록 수정했다. 2026-11-06 GitHub 연결 시 재생성 도구와 원본을 임시 폴더에서 `scripts/wireframes/`로 옮겼다.

## 후속 요구: 공고별 전형 단계

2026-11-01 사용자는 공고 등록 시 각기 다른 채용 절차를 인식하고 지원 상태를 그 절차에 맞게 고를 수 있도록 요청했다. 현재의 공통 상태 선택은 임시 첫 버전이며, 후속 공고 등록 화면에서는 공고별 절차 제안 → 원문 확인·수정 → 현재 단계 선택을 연결한다. 같은 회사도 공고별로 절차가 다를 수 있다.

회사명에 고정된 단계 목록을 붙이지 않는다. 공통 활동 분류는 전체 필터에 사용하고, 실제 전형 상태에는 해당 공고의 과제·코딩테스트·면접 등 현재 단계를 표시하는 방향이다. 자동 추출이 불확실하거나 절차가 없으면 수동 입력한다. 일정은 공고별 단계와 연결하되 날짜만으로 합격이나 단계 통과를 확정하지 않는다.

등록 화면에서 확인한 공고별 단계가 해당 지원 건의 상태 선택지에 반영되도록 미리보기를 연결했다. 자동 인식과 단계 변경 이력의 실제 저장은 구현하지 않았다. 세부 규칙과 후속 완료 기준은 제품 기획서 4절 ‘공고별 채용 절차와 현재 단계’에 기록했다.
