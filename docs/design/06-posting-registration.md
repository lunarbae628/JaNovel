# 공고 등록과 확인

2026-11-01 · 동선과 화면 검토용 미리보기 · 제품 구현 전

## 이번 초안

`wireframes/posting-registration.html`에서 시작한다. 지원 현황의 ‘+ 공고 등록’에서도 같은 화면으로 들어간다. 링크·스크린샷·텍스트 중 하나를 입력하고 정보를 확인한 뒤 공고를 저장하거나 작성 화면으로 이동한다. 기존 작성 화면의 문항별 버전 그래프와 채팅은 유지한다.

확인 화면만 바로 검토할 때는 `wireframes/posting-review.html`을 사용한다. 가상의 예시 공고에서 시작하며 같은 등록·저장 흐름으로 이어진다.

입력과 확인은 별도 화면으로 나눴다. 사용자가 확인 화면의 중복 원문 패널을 불필요하다고 판단해 제거했다. 확인 화면에는 수정할 정보만 한 열로 표시한다. 원문은 입력 자료로 보관하며 저장한 공고 보기에서는 다시 볼 수 있다. 무채색 섹션과 기존 파란 포인트를 유지한다.

## 실제 동작과 예시의 구분

‘예시 결과 보기’는 가상의 라인업랩 공고와 미리 정한 결과를 연다. 실제 URL 수집, OCR, 문항·절차 추출 모델은 호출하지 않는다. 사용자가 넣은 링크·이미지·텍스트에는 임의의 회사·문항·단계를 채워 넣지 않고 직접 입력할 빈 결과를 제공한다. 화면에도 예시 결과와 직접 입력을 구분한다.

입력한 이미지와 텍스트는 미리보기 메모리 안에서만 다룬다. 파일을 서버로 보내거나 외부 사이트를 요청하지 않는다. URL을 원문 링크로 열 때는 http·https만 허용한다. 페이지 새로고침 후 유지되는 저장은 포함하지 않는다.

## 확인할 정보

- 회사명·직무는 필수다. 주요 업무와 자격 요건은 접지 않고 바로 표시한다. 항목별로 수정·추가·삭제할 수 있고, 긴 항목은 입력란 높이가 내용에 맞춰 늘어난다. 빈 항목은 저장할 때 제외한다.
- 선택 항목인 지원 링크는 URL 입력 시 채워 주고, 스크린샷·텍스트로 등록할 때도 직접 추가할 수 있다. 자소서 작성 페이지 맨 위의 회사명 헤더 오른쪽에 ‘지원하러 가기’를 둔다. 공고 확인·공고 보기와 지원 현황에서도 접근할 수 있다. 링크가 없거나 유효하지 않으면 버튼을 비활성화하고, 유효한 http·https 링크를 입력하면 새 탭으로 여는 링크로 즉시 바뀐다. 예시 공고에는 실제 지원 주소를 임의로 넣지 않는다.
- 마감일과 시간은 별도다. 시간을 모르면 비워 두며 23:59를 붙이지 않는다. 날짜 미확인과 상시채용을 구분한다.
- 채용 절차의 이름·순서를 수정하고 단계를 추가·삭제한다. 확인된 절차가 없어도 저장할 수 있다. 단계마다 식별자를 두어 순서를 바꿔도 이름과 선택지가 어긋나지 않게 한다.
- 문항 본문·최대 글자 수·공백 포함 조건을 고친다. 문항이나 제한을 모르면 비워 둔다. 이번 화면은 글자 수 조건만 다루며 바이트 제한은 후속 상세 설계다.

## 저장 이후

공고 저장은 지원 현황으로 돌아가고, 저장 후 작성은 해당 공고의 문항으로 빈 답변을 시작한다. 기존 예시 답변을 새 지원 건에 복사하지 않는다. 등록한 글자 수와 공백 조건이 작성 화면의 계산에 반영된다. 문항 없이 저장한 경우 작성 화면에서 문항을 추가할 수 있다.

지원 현황의 상태 선택은 공통 활동 분류와 해당 공고의 절차를 한 선택기에서 구분해 제공한다. 사용자가 특정 단계를 선택하면 공통 분류는 ‘전형 진행’이 되어 전체 필터에도 반영된다. 절차를 등록했다는 이유로 제출·합격·단계 통과를 자동 확정하지 않는다.

목록의 ‘공고 보기’에서 저장 당시 원문과 확인한 업무·요건·문항·절차를 다시 볼 수 있다. 원문은 확인 과정에서 바꾼 정보와 분리한다. 마감일은 캘린더에 반영한다. 같은 회사라도 지원 건별 절차와 문항은 독립적이다.

## 검증과 남은 범위

브라우저에서 링크 검증, 원문과 수정 결과 분리, 단계 수정·이동·추가·삭제, 문항과 글자 수 조건 전달, 빈 문항 후속 추가, 서로 다른 절차 선택, 목록 필터·캘린더 반영, 스크린샷 선택·표시, 기존 초안 보존을 확인했다. 1200·1024·736·375·320px에서 가로 넘침과 실행 오류가 없었다. 기록은 `_workspace/2026-11-01-application-overview/registration-verification.json`이다.

추출 품질·실제 데이터 저장·원문 보관 정책은 이 검증에 포함되지 않는다. 등록 후 공고 정보 수정과 기존 문항 이력의 연결, 전형 단계 변경 이력, 일정과 단계 식별자의 연결, 바이트 제한, 중복 공고 판별은 구현 전 상세 설계 대상으로 남긴다. 이번 화면 추가가 제품 기획서의 초기 수동 입력 범위를 자동 추출 구현으로 바꾼 것은 아니다.
