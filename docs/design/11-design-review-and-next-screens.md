# Figma 검토와 다음 화면

2026-11-07 · 디자인 검토 · 제품 구현 전

후속 상태(2026-11-08): 사용자는 디자인 검토를 먼저 마무리하고 AI 연결 실험을 뒤로 미루기로 했다. 공고 입력·지원 상세·제출본·달력과 주요 예외 상태를 Figma에 추가했다. 아래 내용은 반영 전 진단이며 현재 화면과 한계는 [핵심 화면 검토](14-core-screens-and-review.md)를 따른다. 웹 내부 AI 채팅은 유지한다.

## 판단

작성 화면의 기본 배치는 유지한다. 무채색 세 영역, 문항별 이력, 가운데 작성·비교와 오른쪽 피드백, 회사 헤더의 지원 현황 이동·지원 링크는 사용자의 요청과 맞는다. 주변 노드와 확장된 전체 그래프도 한 디자인 안에서 표현했다. 남는 작성 공간을 설명·카드로 채울 필요는 없다.

다만 현재 Figma는 작성·비교의 기본 상태를 표현한 초안이다. 분기·병합을 수행하는 화면, AI 후보 채택, 제출본과 지원 현황까지 이어지는 흐름이 없어 디자인 확정이나 구현 준비 완료로 볼 수 없다. 기존 HTML 시안에 동작이 있다는 사실을 Figma에 해당 화면이 있다는 뜻으로 해석하지 않는다.

## 확인한 범위

- 직전 작업에서 내보낸 작성·버전 비교·사이드바 확장 화면의 캡처와 레이어 검사 결과를 검토했다. 최신 그래프 결과는 `surrounding-graph-result.json` 기록을 기준으로 한다.
- 제품 기획서와 디자인 문서 05~10, 로컬 시안의 비교·분기·병합 코드를 대조했다.
- 이번 검토의 Figma 실시간 조회는 응답 시간 초과로 실패했다. 이후 사용자의 변경 유무는 확인하지 못했다. 모바일·집중·스냅샷 창은 기존 검수 기록만 있으며 이번에 새로 캡처하거나 조작하지 않았다.
- 실제 사용자 사용성 시험, 채팅·MCP 연결, 저장·복구, 화면 간 클릭 왕복을 이번에 시험한 것은 아니다.

## 고쳐야 할 부분

### 1. 외부 AI 경로와 화면의 불일치

기획서는 외부 ChatGPT에서 MCP로 맥락을 읽는 경로가 우선이다. 반면 현재 채팅 영역은 서비스 안에서 요청·응답이 이뤄지는 모습이다. 서비스용 Talk to Figma 연결 성공은 JaNovel 제품의 ChatGPT 연동 검증과 별개다.

실제 제품 연결 실험 후 오른쪽 패널의 동작을 확정해야 한다. 외부 경로로 시작한다면 연결 상태·선택한 문항과 버전 전달·외부 AI로 이동·수정 후보 가져오기가 필요하다. 내부 대화를 유지하려면 지원되는 호출·인증·비용 경로를 먼저 확인한다. 이번 검토에서 경로를 바꾸거나 가능하다고 확정하지 않는다.

AI 후보 비교에는 요청 당시 원문, 수정 제안, 채택·취소, 요청 이후 작성본 변경 상태가 필요하다. 후보 도착이나 저장만으로 현재 답변을 덮어쓰지 않는다.

### 2. 버전관리의 작업 흐름이 덜 완성됨

작업 도구에 병합 버튼은 있지만 어떤 두 기록을 고르고 결과를 확정하는지 Figma에서 볼 수 없다. 분기 이름·설명 입력, 분기 시작 후 작성 상태, 병합의 문단 선택·직접 수정·새 스냅샷 생성, 취소·미저장 답변 보호를 연결한다. 과거 기록으로 복원하는 것은 별도 선택으로 제공한다.

스냅샷 버튼을 누를 때마다 이름을 강제로 작성하게 하지 않는다. 이름·설명은 선택 사항이다. 내용이 같을 때 기록 생성 버튼이 기존 이름·설명 수정으로 바뀌는 HTML 시안 동작은 기대와 다를 수 있으므로 메타데이터 수정 진입점과 분리하는 방향을 제안한다.

### 3. 그래프 확장과 긴 기록

기본 그래프는 작은 예시에서 읽기 쉽다. 다만 ‘직접 연결된 주변’도 자식 분기가 많으면 복잡해지므로 그 정의만으로 표시 개수가 제한되지는 않는다. 선택 노드와 병합의 두 부모를 우선하고, 자식이 많으면 일부와 나머지 개수로 요약하는 규칙이 추가로 필요하다. 정확한 개수는 아직 정하지 않았다.

확장 상태는 사이드바 520px·가운데 558px이다. 비교 본문은 열마다 약 234.5px이므로 14px 한글에서 한 줄에 약 16~17글자만 들어간다. 짧은 예시는 겹치지 않지만 긴 자소서를 오래 읽기에는 좁다. 전체 보기를 이력 탐색 상태로 사용하고 충분히 읽을 때 주변 보기로 돌아오도록 하거나, 별도의 본문 폭 확보 동작을 후속 시안에서 검토한다. 사용자 요청 없이 전체 보기를 다시 모달로 바꾸지 않는다.

현재 이름 폭은 124px이고 HTML의 이름 입력 한도는 60자다. 긴 이름의 줄임표·전체 이름 확인, 생략된 구간이 직접 연결처럼 보이지 않는 표시, 부모가 많은 예시를 검토해야 한다. 원 크기를 키우는 것으로 해결하지 않는다.

### 4. 비교와 작성 상태

오른쪽의 파란 강조만으로는 삭제만 한 수정을 알아보기 어렵다. 빨간색 없이 왼쪽의 해당 구절을 중립 배경으로 표시하거나 변경 구간 표시를 제공하는 방향을 제안한다. 문단 삽입·재배치 예시도 필요하다.

초안 자동 보관과 명시적 스냅샷을 구분하고, 보관 중·실패·재시도·복구 상태를 작은 표시로 제공해야 한다. 모든 상태를 별도 페이지로 만들 필요는 없다. 첫 스냅샷 이전의 빈 답변도 v1 기록과 구분한다. 문항 전환 시 그래프·초안·대화가 각각 바뀌는지와 긴 문항·10개 문항의 탭 처리를 확인한다.

## 추가할 화면과 우선순위

| 순서 | 디자인 묶음 | 완료 확인 |
| --- | --- | --- |
| 1 | 작성 화면의 분기·병합·복원·AI 후보 비교/채택, 빈 화면·저장 실패 상태 | 한 문항에서 수정·기록·분기·병합·과거 복원까지 이어지고 원본이 보존되는 과정을 설명할 수 있음 |
| 2 | 제출본 지정과 열람 | Q1의 v4와 Q2의 v2처럼 다른 버전을 묶고 이후 수정에도 당시 내용이 고정됨. ‘지원하러 가기’ 클릭을 실제 접수로 처리하지 않음 |
| 3 | 지원 현황 목록·캘린더, 일정 추가/수정/삭제 | 작성·제출본으로 왕복하고 마감·면접·과제가 구분됨. 회사별 실제 절차와 전체 활동 분류가 혼동되지 않음 |
| 4 | 공고 등록·정보 확인/수정 | URL·이미지·텍스트 입력과 문항·업무·요건·절차를 수정해 작성으로 이어짐. 실제 추출이 없는 상태를 정직하게 표현함 |

이는 네 묶음이며 모든 상태를 독립 페이지로 늘리라는 뜻은 아니다. 이름·설명, 복원 확인, 일정 변경은 대화상자나 기존 영역의 상태로 충분하다. AI 연결 실험은 1번과 병행해 제품의 호출 경로를 먼저 확인한다.

주간 추천·음성 면접·결제·랜딩 페이지는 현재 디자인 완료 조건에 넣지 않는다. 로그인·연결 설정은 실제 배포·인증 방식이 결정되면 필요한 최소 범위로 추가한다.

## 디자인을 확정할 기준

공고 등록 → 두 문항 작성 → 스냅샷 → 분기 → 비교·병합 → AI 후보 검토·채택 → 문항별 버전을 묶은 제출본 지정 → 일정 변경 → 제출본 재확인을 대표 시나리오로 삼는다. 프로토타입에서 막히는 이동과 필요한 상태를 먼저 해결한 뒤 구현 계획을 작성한다. Figma 클릭 시안 통과와 실제 저장·AI·상태 보존 기능 구현은 구분한다.

다음 작업은 작성 화면 전체를 다시 꾸미는 것이 아니라 **분기·병합 작업을 끝내는 화면**을 기존 디자인에 추가하는 것으로 권고한다. 이 검토에서는 Figma 화면을 새로 추가하거나 변경하지 않았다.

## 후속 반영

같은 날 사용자의 진행 요청으로 분기 만들기·문단 선택 병합·병합 결과 확인 상태를 Figma에 추가했다. [반영 내용과 검수 범위](12-branch-merge-screens.md)를 따른다. 위 표의 ‘분기 생성·병합 화면 없음’은 반영 전의 진단이다. 복원·AI 후보 채택·새 전환 연결과 예외 상태가 모두 끝났다는 뜻은 아니다. AI 채팅 위치와 사용자 API 키 선택지는 [별도 검토](../planning/04-ai-chat-options.md)에 기록했다.
