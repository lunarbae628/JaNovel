# 일정 직접 추가와 예상 질문 답변

2026-11-14 · 사용자 요청에 따른 디자인 수정안. 프론트는 수정하지 않는다.

## 일정

- 화면에는 ‘개인일정’ 대신 ‘일정’을 쓴다. 회사 연결 여부는 데이터 속성으로 구분하며 사용자에게 불필요한 항목 구분을 먼저 선택시키지 않는다.
- `추가` 버튼은 유지하고 빈 날짜 칸을 클릭해도 같은 추가 창을 연다. 시작일·종료일에는 클릭한 날짜를 채운다.
- 빈 날짜 칸에서 드래그하면 선택 범위를 강조하고 놓을 때 추가 창을 연다. 선택한 처음·마지막 날짜를 채우고 날짜 순서는 정규화한다. 기존 일정을 클릭하면 상세·수정을 열며 새 일정 추가와 구분한다.
- 선택 중 Esc로 취소할 수 있게 한다. 드래그를 단순 클릭과 구분하고, 월·주 경계를 넘는 선택도 하나의 기간으로 처리한다. 모바일·키보드에서도 버튼을 통한 기간 입력은 유지한다.
- 기간, 매일 반복, 일반 일정·체크리스트, 색상은 유지한다. 관리 방식 변경만으로 제목·기간·기록을 초기화하지 않는다.

[FullCalendar의 날짜 범위 선택](https://fullcalendar.io/docs/selectable)은 클릭·드래그 선택을 지원하는 구현 참고다. 라이브러리를 채택하거나 설치했다는 뜻은 아니다. [선택 결과의 종료일은 배타적](https://fullcalendar.io/docs/select-callback)이므로 채택 시 UI의 포함 종료일과 변환을 맞춰야 한다.

Figma에는 하루 클릭과 11월 16~18일 드래그의 대표 전환을 연결한다. 임의 좌표의 실시간 범위 계산·실제 날짜 입력·저장은 후속 프론트 작업이며 Figma의 고정 전환으로 완료했다고 간주하지 않는다.

## 예상 질문과 답변

기준 자료가 차지하던 본문 왼쪽 패널을 제거하고 상단 `자료` 버튼으로 옮긴다. 버튼에서 제출본·공고를 확인하거나 기준을 변경한다. 자료와 출처는 유지하되 항상 넓은 공간을 차지하지 않도록 한다.

본문은 질문 목록과 선택한 질문의 답변으로 나눈다. 선택한 질문은 큰 제목, 답변은 읽고 편집할 수 있는 넓은 본문으로 제공한다. 문항별 근거는 짧은 출처 링크로 둔다. 질문마다 직접 작성한 답변을 따로 기록하고 질문을 오가도 유지한다. 저장 실패 시 입력을 유지하고 재시도할 수 있어야 한다.

**예상 질문 페이지의 텍스트 답변 기록**과 **음성 모의면접**은 별개다. 모의면접에는 타이핑 답변 입력을 추가하지 않는다. 준비한 답변·모의면접 전사·실제 제출본도 각각 구분하며 서로 자동 덮어쓰지 않는다.

## 문구 정리

현재 위치·날짜·상태·출처·필드 이름·권한 안내처럼 판단과 행동에 필요한 문구는 남긴다. 이미 화면으로 드러나는 사용 설명, 같은 회사·화면 경로의 반복, 질문 목록 옆의 긴 소개 문장은 제거한다. 음성 입력 상태·저장 상태·기간·반복 수정 범위처럼 실수를 막는 정보는 유지한다.

Figma 적용과 구조·연결 검사는 새 채널 연결 후 수행한다. 기획 문서와 수정 스크립트 준비만으로 디자인 적용 완료를 보고하지 않는다. 보고에는 이미지를 첨부하지 않는다.
