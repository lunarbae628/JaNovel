# 선택 기록을 따라 이동하는 버전 지도

2026-11-10 · 기술 검토와 디자인 반영

## 결론

프론트에서 구현할 수 있다. Docsa 프론트는 이미 `reactflow` 11.11.4로 그래프를 그리고 이동·확대를 지원한다. 선택한 기록을 중심으로 카메라를 이동시키는 기능을 추가하면 된다. 별도 게임 엔진이나 Canvas 엔진은 필요하지 않다.

이번에는 기존 Docsa 코드를 수정하지 않았다. Figma 디자인과 별도의 React Flow 동작 검토 화면을 만들었다. 실제 자소서 본문·서버·저장과 연결한 제품 구현은 아니다.

## 기존 코드에서 확인한 점

- `DocumentGraph.tsx`는 `reactflow`에서 가져온 React Flow 11을 사용한다. `@xyflow/react` 12도 의존성에 있지만 이 그래프의 실제 import는 11이다. 두 패키지를 섞지 않고 기존 버전을 먼저 재사용한다.
- `panOnDrag`, `panOnScroll`, `zoomOnPinch`가 이미 있다. `AutoFitView`는 노드 수·엣지 수·컨테이너 크기가 바뀔 때마다 전체를 맞춘다.
- `flowKey`가 갈래·기록·엣지 수로 만들어져, 기록 추가 시 그래프가 재마운트될 수 있다. 현재 위치 유지에는 이 동작도 바꿔야 한다.
- `useGraphData.ts`는 부모 관계의 깊이와 갈래 인덱스로 위치를 계산한다. 카메라 구현과 별도로 갈래 ID별 레인을 안정적으로 유지해야 새 갈래가 생겼을 때 기존 경로가 갑자기 움직이지 않는다.

참고: [React Flow viewport API](https://reactflow.dev/api-reference/types/react-flow-instance), [이동·확대](https://reactflow.dev/learn/concepts/the-viewport), [성능 지침](https://reactflow.dev/learn/advanced-use/performance). 위 공식 문서는 현재 버전 기준이므로 11의 세부 타입은 설치된 패키지와 동작 시안에서도 확인했다.

## 적용할 동작

| 상황 | 동작 |
|---|---|
| 문항을 처음 열기 | 해당 문항의 선택 기록 또는 작성 중 초안에 포커스 |
| 기록 선택 | 같은 지도 좌표에서 카메라만 약 320ms 동안 이동 |
| 직접 드래그·스크롤 | 탐색한 위치를 유지하고 자동으로 되돌리지 않음 |
| 선택 기록으로 돌아오기 | 선택 노드로 재중앙 정렬 |
| 전체 보기 | 같은 사이드바를 208px에서 400px로 넓히고 전체 범위를 맞춤 |
| 주변 보기 | 사이드바를 줄이고 선택 기록을 읽을 수 있는 배율로 복귀 |
| 단순 패널 크기 변경 | 보고 있던 지도 좌표를 유지. 무조건 전체 맞춤을 호출하지 않음 |
| 본문 입력·AI 응답·비교 대상 변경 | 지도 위치를 자동으로 바꾸지 않음 |
| 움직임 줄이기 설정 | 카메라 전환 시간을 0으로 설정 |

카메라는 `setCenter`, 전체 범위는 `fitView`, 배율·위치 유지는 viewport 상태로 처리한다. 문항별 viewport와 선택 기록은 별도로 관리한다. 사용자가 지도를 이동하는 것과 기록을 분기하는 것은 서로 다른 동작이다.

노드 자체는 드래그로 옮기거나 연결하지 않는다. 배경을 드래그해 지도를 탐색하고 노드 클릭은 기존처럼 해당 본문을 연다. 작성 중 초안을 선택하더라도 스냅샷을 자동 생성하지 않는다.

## 디자인 변경

- `숨긴 기록 · n개`를 제거했다.
- 선택 기록을 패널 중간 부근에 두고 부모와 후속 기록이 위아래로 이어지게 했다. 화면 밖으로 나가는 경로는 뷰포트에서 자연스럽게 잘린다.
- 작은 원형 노드를 유지하고 선택 위치에 블루 원과 옅은 링을 사용한다. 선택 기록과 직접 연결된 경로만 강조한다.
- 넓힌 패널에는 같은 기록들이 같은 관계로 나타난다. 본문·비교 대상·채팅 영역의 내용은 바꾸지 않는다.
- Figma 레이어는 편집 가능한 노드·텍스트·벡터다. 이미지로 그래프 전체를 덮지 않았다.

추가 디자인 검토에서 갈래 간 가로 간격을 144→104px, 같은 경로의 노드 세로 간격을 128→88px로 줄였다. 글자 크기는 유지하며 선택 라벨 폭은 108px, 일반 라벨은 88px, 선택 링은 26px로 정리했다. 전체 보기에서도 충분한 공간이 있으면 노드·글자를 축소하지 않고 같은 간격으로 보여준다. 동작 검토 시안의 노드 클릭 영역 폭은 96px로, 104px 레인 안에서 겹치지 않게 했다.

그다음 검토에서 가로 간격을 다시 104→80px로 줄였다. 이 단계의 기준은 가로 80px / 세로 88px였다. 노드 클릭 영역·Figma 라벨은 72px, 안쪽 글자 영역은 68px로 제한했고 세로 간격·글자 크기는 유지했다.

후속 검토에서는 기본 포커스 배율을 **125%**로 높였다. 확대 후에도 간격이 다시 벌어지지 않도록 지도 좌표는 가로 60px / 세로 76px로 조정한다. 실제 화면에서는 가로 약 75px / 세로 약 95px로, 직전 80px / 88px보다 브랜치는 조금 가깝고 세로는 조금 넉넉하다. 지도 좌표에서 노드 클릭 영역은 56px, 라벨 안쪽은 52px이며 확대하면 각각 70px, 65px다. Figma도 이 확대된 크기로 표현한다. 전체 보기는 최대 125%까지 사용하되 기록이 많으면 전체 범위에 맞춰 축소한다.

선택 강조는 노드와 해당 라벨에만 적용한다. 모든 연결선은 같은 중성 회색 `#CDD2DC`를 사용하며, 선택 노드의 앞뒤 경로가 파랗게 변하거나 두꺼워지지 않는다. 작성 중 초안으로 이어지는 점선은 기록 종류를 구분하는 표시로 유지한다.

### 긴 기록 이름과 메시지

- 그래프는 버전 표시와 이름 한 줄을 보여준다. 이름은 고정된 라벨 폭 안에서 말줄임하며 원문을 변경하지 않는다. Figma도 원래 문자열을 보존하고 한 줄 `ENDING` 말줄임을 사용한다.
- 선택한 노드도 라벨을 옆으로 넓히지 않는다. 인접 브랜치의 클릭 영역은 겹치지 않는다.
- 메시지는 지도에 펼쳐 놓지 않는다. 선택한 기록의 본문 위에서 `기록 정보`를 열어 전체 이름과 메시지를 확인하는 흐름을 사용한다.
- 동작 시안에서는 이름에 마우스를 올려 전체 이름을 볼 수 있고, `기록 정보`에서 줄바꿈을 보존한 메시지 전체를 확인할 수 있다. 이 상세 정보 인터랙션은 React Flow 검토 시안에 반영했으며 Figma의 모든 기록별 상세 팝업을 새로 연결한 것은 아니다.
- 비교 헤더의 이름과 대상 선택창도 한 줄 말줄임으로 영역 침범을 방지한다. 저장 데이터나 입력 글자 수를 그래프 너비 때문에 잘라내지 않는다.

검토 화면 하단의 `긴 이름·메시지 예시`를 켜면 인접한 두 긴 이름을 같은 지도에서 확인할 수 있다. 해당 체크박스는 제품 기능이 아닌 검토 도구다.

Figma는 선택별 포커스 상태와 넓힌 지도 모양을 표현한다. 임의 위치로의 자유로운 카메라 이동·확대·복귀 검증은 React Flow 시안에서 수행한다. Figma의 정적 화면을 실제 카메라 구현 완료로 판단하지 않는다.

## 동작 시안

원본은 `scripts/wireframes/graph-map-preview.jsx`와 `graph-map-preview.html`, 생성 도구는 `build-graph-map-review.mjs`다. 제품의 의존성을 바꾸지 않고 Docsa에 설치된 React Flow 11과 esbuild를 읽어 별도의 로컬 산출물을 만든다.

```sh
node scripts/wireframes/build-graph-map-review.mjs
python3 -m http.server 8976 --bind 127.0.0.1 --directory _workspace/2026-11-10-graph-map
```

다른 환경에서는 `GRAPH_REVIEW_MODULES`로 React 19, React DOM, React Flow 11, esbuild가 설치된 폴더를 지정한다. 산출물은 `_workspace/2026-11-10-graph-map/`에만 쓴다.

[로컬 동작 시안](http://127.0.0.1:8976)에서 기록 선택, 드래그, 확대·축소, 선택 위치 복귀, 전체 보기, 200개 예시를 확인할 수 있다. 하단의 기록 선택·200개 예시는 검토 도구이며 제품 화면에 넣을 버튼이 아니다. 중앙 본문과 AI 응답은 고정된 예시다.

## 확인한 범위와 남은 일

브라우저에서 선택 기록 이동, 직접 이동한 위치 유지, 전체 보기와 복귀를 확인했다. 200개 예시를 전체 보기로 맞췄을 때 200개 노드의 화면 경계가 뷰포트 안에 들어오는 것도 확인했다. 이 결과는 기능 검토이며 수천 개 기록의 프레임 속도나 실제 API 응답에 대한 성능 보장은 아니다.

Figma에서는 패널 변형 99개를 읽었다. 기록이 있는 지도 94개는 노드와 라벨의 키가 일치하고, 중복 위치가 없으며, 선택한 기록이 실제 지도에 존재하는 것을 확인했다. 나머지는 기록이 없는 상태다. 기존 작업·비교 시안 217개에는 `숨긴 기록` 문구가 보이지 않도록 정리했다. 검토 데이터의 노드 참조도 새 지도 구조에 맞췄다.

반영 전후 Figma에서는 노드 ID·라벨·부모 경로·선택 표시·클릭 대상을 점검한다. 기록이 늘어도 같은 위치를 유지하도록 문항별 좌표·viewport 관리가 필요하다. 실제 구현에서는 노드/엣지 메모이제이션, 화면 밖 렌더링 최적화, 긴 라벨 표시, 키보드 탐색을 함께 검증한다. 복잡한 병합에서 선이 많이 겹치는 경우에만 추가 배치 엔진을 검토한다.

Figma 도구는 `scripts/figma/graph-map-tools.js`, 실행 도구는 `graph-map.mjs`다. 이 수정으로 그래프 내용이 한 단계 더 안쪽인 `버전 지도 · 고정 좌표` 안에 들어갔으므로, 이후 점검 도구는 그래프의 직접 자식만 가정하지 않는다.
