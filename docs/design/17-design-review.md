# JaNovel 디자인 점검

2026-11-09 · 현재 Figma를 읽어 확인한 프로토타입 검토 · 수정 전

이 문서는 보완 전 점검 기록이다. 이후 반영한 내용과 재검증 범위는 [제품 디자인 고도화 결과](18-product-design-workflow.md)에 정리했다.

## 판단

디자인 확정 전에 회사·문항 맥락, 제출 버전 선택, 병합·스냅샷 완료 상태, 패널 접기를 보완해야 한다. 클릭 대상이 존재한다는 검사만으로 선택 결과까지 맞다고 판단할 수 없다. 이번에는 이동 후의 회사·문항·본문·선택값을 함께 대조했다.

프로덕션 기능 검사가 아니라 Figma 디자인·시연 흐름 검사다. 저장이나 AI API가 아직 연결되지 않았다는 사실과, 시연 화면이 잘못된 결과를 보여주는 문제는 구분한다.

## 먼저 고칠 문제

### 1. 회사·문항 맥락이 바뀌는 이동 — P1

- [Q2 작성](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=42-2327)의 ‘수정안 비교’는 Q1 지원동기용 AI 수정안 `42:458`로 이동한다. Q2 문제 해결 경험의 후보·대화·비교 대상이 유지되지 않는다.
- [솔빛테크 지원 상세](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=67-18270)의 ‘자소서 작성’은 모노랩 작성 화면 `5:530`으로 이동한다.
- 수정 기준: 이동 전후 지원 건과 문항이 같아야 한다. 같은 레이아웃을 재사용하더라도 회사·문항·본문·대화의 맥락을 유지하는 시연 상태를 연결한다.

### 2. 제출 버전 선택이 반영되지 않음 — P1

- [제출 버전 선택](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=42-1365)에서 Q1의 v3나 v3-A를 고르면 모두 원래 선택 화면으로 돌아온다. 그 화면의 선택값은 계속 v4다.
- Q2의 v1을 골라도 표시값은 v2로 남는다. 고정본도 Q1 v4·Q2 v2의 예시 한 가지로 연결돼 있다.
- 수정 기준: 선택한 버전의 이름과 본문이 선택 화면, 고정 확인, 고정본까지 같아야 한다. 작성 중 초안과 제출 버전은 계속 구분한다.

### 3. 병합·스냅샷 완료 후 결과가 맞지 않음 — P1

- [병합 화면](https://www.figma.com/design/ArLSPAcNklUKhcpk8V4zyf?node-id=37-441)에서 오른쪽 ‘문서 버전 관리’를 선택하면 중앙 결과에 그 구절이 반영된다.
- 이름·설명 창과 완료 확인을 거친 뒤에는 항상 v4 본문 `67:3049`가 열린다. 그 본문의 해당 구절은 ‘데이터 저장’이다. 선택한 병합 결과와 최종 본문이 다르다.
- 일반 스냅샷도 완료 확인 후 기존 작성 화면으로 돌아가며, 새 이름·기록이 그래프에 추가된 상태가 없다.
- 수정 기준: 고른 구절과 이름·설명이 결과 본문에 이어져야 한다. 완료 상태에서 새 기록과 부모 관계를 그래프에 보여준다. 완료 알림은 별도 확인창보다 작은 알림으로 줄일 수 있다.

### 4. 패널 접기에서 비교 상태 초기화·내용 노출 — P2

- v3와 작성 중 초안을 비교하는 화면 `67:2743`의 양쪽 접기 버튼은 모두 기존 집중 작성 `5:790`으로 이동한다. 선택한 스냅샷과 오른쪽 비교 대상이 유지되지 않는다.
- 기존 비교 화면의 접기도 새 대상 선택이 없는 옛 비교 화면으로 이어진다.
- 오른쪽을 접은 상태 6개에서는 AI 패널 전체가 화면 밖으로 밀린다. 캡처에서 좁은 가장자리에 채팅 글자와 입력창 조각이 보이고, 펼치기 화살표 방향도 맞지 않는다.
- 수정 기준: 현재 문항·왼쪽 기록·오른쪽 대상은 유지하고 패널 너비만 전환한다. 접힌 패널에는 펼치기 버튼만 남긴다.

## 추가 정리

- 진행 단계 선택창 `67:10951`의 ‘닫기’ 버튼이 하단에서 잘린다. 내용에 맞게 높이를 잡거나 스크롤 범위를 지정해야 한다.
- 오른쪽 비교 대상을 정한 뒤 ‘병합’을 누르면 별도의 상대 선택을 다시 한다. 비교 대상과 병합 대상이 별개라는 정책이 아직 분명하지 않다. 선택한 비교 대상을 병합의 기본값으로 사용하는 방향을 권장한다. 작성 중 본문을 병합할 때도 자동으로 스냅샷을 생성하지 않도록 구분해야 한다.
- 이전 노드 메뉴, 복원 확인, 반복된 예시 상태는 현재 진입 흐름과 분리해 보관하는 편이 파일 검토에 유리하다. 이번 점검에서는 삭제하지 않았다.

## 확인된 항목

- 현재 Figma의 화면·상태 226개와 클릭 노드 3,618개를 읽었다. 존재하지 않는 이동 목적지는 0개다. 이 수치는 이전 시안·예외 상태도 포함하며 모든 동작의 의미가 맞다는 뜻은 아니다.
- 비교 시안 76개에서 좌우로 표시되는 본문을 원본 문자열과 대조했다. 대상 변경 64개에서 왼쪽 기록 유지와 ‘작성 중’ 복귀가 맞았다.
- ‘이 기록으로 복원’ 버튼과 지원 목록의 항목명 행은 남아 있지 않았다.
- 한글 폰트는 Noto Sans KR로 일치했다.
- 화면 전체 경계 밖의 텍스트는 7개 상태의 49개였다. 오른쪽 패널 접기 상태 6개와 단계 선택창 1개에 모여 있었고, 캡처로 내용 노출과 잘림을 확인했다. 모든 부모 컨테이너의 잘림이나 반응형 검증을 끝냈다는 뜻은 아니다.
- 실제 Figma 미리보기에서 작성 화면 배치를 확인했다. 모든 동선을 포인터로 직접 왕복한 검사는 아니다. 자유 입력·실제 저장·공고 추출·AI 호출·동기화 성공도 이번 검증에 포함하지 않는다.

검사 원본은 `_workspace/2026-11-09-design-review/`의 `trees.json`, `reactions.json`, `audit.json`, `compare-review.json`이다. 읽기 검사 소스는 `scripts/figma/audit-design.mjs`다. Figma 시안은 이번 점검에서 수정하지 않았다.
