# 화면 점검과 다음 단계

2026-11-02 · 현재 와이어프레임과 기획서 기준 · 제품 코드 구현 전

## 판단

작성 화면의 기본 배치는 유지할 만하다. 문항별 그래프, 가운데 작성·비교·병합, 오른쪽 대화의 역할이 분리돼 있고 양쪽 패널을 접을 수 있다. 다음 작업은 색상 조정보다 제출 이후까지 이어지는 사용 흐름과 AI 연결의 불확실성을 해소하는 데 둔다.

이는 사용성 검증을 마쳤다는 뜻은 아니다. 현재는 예시 데이터와 메모리 상태로 움직이는 시안이다. 실제 공고 추출, 모델 호출, MCP, 서버 저장은 연결하지 않았다.

## 사용성에서 더 확인할 부분

- 새 지원 건에도 빈 본문이 v1로 표시된다. 첫 실제 스냅샷 전의 빈 상태와 기록을 구분하는 편이 이해하기 쉬울 수 있다.
- 내용이 같을 때 ‘스냅샷’은 기존 이름·설명을 수정한다. 기록을 만든다는 기대와 다른 동작이므로 안내나 정보 수정 진입점을 검토한다.
- 스냅샷마다 이름·설명 입력창을 여는 것이 실제 작성 속도를 늦추는지 관찰한다. 필수 입력으로 바꾸지 않는다.
- 긴 문항, 문항 10개, 스냅샷 30개, 여러 분기에서 탭과 그래프를 추가 확인한다. 현재 소수 문항·기록 예시의 배치 검증만으로 충분하다고 보지 않는다.
- 공고별 절차를 골라도 ‘대기·진행·통과·탈락’의 구분은 아직 상세 설계가 필요하다. 특히 서류 전형 선택을 제출 완료로 해석하지 않는다.

## 권장 진행 순서

1. **실제 지원 한 건으로 시나리오 점검.** 공고 등록 → 두 문항 작성 → 스냅샷 → 과거 비교 → 피드백 후보 비교·채택 → 제출본 지정 → 면접 일정 변경 → 제출본 재확인을 따라간다. 막히는 곳과 번거로운 조작만 기록한다. 현재 시안에는 실제 개인정보 대신 대체 자료를 쓰며, 새로고침하면 입력이 사라진다는 점을 전제로 한다.
2. **빠진 핵심 동선 보완.** 제출본·복원·등록 정보 수정·일정 수정과 저장 상태를 와이어프레임에서 연결한다. 작성 화면의 전체 배치는 유지한다.
3. **AI 연결 실험과 Docsa 읽기 검토.** 실제 계정의 MCP 연결부터 확인하고, 문항·답변 스냅샷·피드백 후보를 기존 코드가 어떻게 수용하는지 읽기 전용으로 검토한다. 원본 코드 수정·복사·저장소 구성은 별도 작업이다.
4. **Figma 디자인 확정.** 확인된 동선을 편집 가능한 화면과 컴포넌트로 정리한다. 기본 화면과 함께 빈 화면·저장 실패·AI 연결 실패·작은 화면을 포함한다.
5. **구현 계획.** 지원 건·문항·초안·불변 스냅샷·분기/병합 관계·제출본·피드백 후보의 저장 규칙과 API를 정한다. 첫 개발 묶음은 공고 수동 등록 → 문항 작성 → 영속 저장 → 스냅샷 → 비교·복원으로 잡고, 이후 제출본·일정·검증한 AI 경로를 연결하는 순서를 제안한다. 요청한 분기·병합 기능을 삭제하는 결정은 아니다.
6. **실제 지원 3건에 사용.** 변경점 확인, 피드백 반영, 제출본 찾기, 일정 정정에 걸린 시간과 실수를 기록한다. 주간 추천·음성 면접·자동 수집 확장은 그 뒤 판단한다.

모델 배정은 기존 기획서 9절을 따른다. 흐름·시안·Figma 반복 작업은 Sol, 데이터·AI 경로와 구현 계획의 큰 판단은 Astra 권장이다. 현재 채팅의 모델을 자동 변경했다는 뜻은 아니다.

## 이번 점검의 근거와 한계

- 현재 작성 화면과 공고 등록 화면을 이미지로 검토하고 기획서·시안 코드와 비교했다.
- 작성 화면 검증 2종을 새로 실행해 문항·도구 줄, 이름·설명, 취소·Escape, 중복 기록 방지, 분기 부모, 수동 병합의 두 부모, 다른 문항과의 분리, 비동기 응답·화면 크기 변경 중 입력 유지를 확인했다.
- 두 검증에서 1200·1024·736·375·320px 가로 넘침과 실행 오류는 없었다. 모든 콘텐츠 길이와 접근성을 검증한 결과는 아니다.
- 공고 등록 점검 중 임시 브라우저 미리보기가 이전 버전임을 발견했다. 원본 시안에는 있는 입력 확인 동작이 미리보기에는 없었으며, 최신 원본으로 미리보기를 재생성했다. 제품 코드 변경은 하지 않았다.
- 최신 미리보기로 공고 등록 검증을 다시 실행해 URL 검증, 예시와 직접 입력 구분, 절차·문항 편집과 가져오기, 글자 수 조건, 스냅샷, 목록·캘린더 연결, 이미지 입력과 기존 초안 유지를 확인했다. 이 검증도 1200·1024·736·375·320px에서 가로 넘침과 실행 오류가 없었다. 합성 JavaScript 구문 검사도 통과했다.
- 검증 원본: `_workspace/2026-11-01-collapsible-editor/named-records-check.cjs`, `branch-merge-check.cjs`, `_workspace/2026-11-01-application-overview/registration-check.cjs`. 브라우저 결과는 각 폴더의 검증 JSON에 남긴다.

공개 서비스의 인증·권한·백업, 실제 AI 품질, 배포 비용과 Docsa 상세 재사용성은 이번 점검 결과에 포함하지 않는다. 현재 화면의 정돈만으로 제품 경쟁력이나 실제 취업 성과를 입증할 수 없다.
