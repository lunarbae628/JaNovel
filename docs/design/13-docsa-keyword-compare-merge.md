# Docsa 기준 비교·병합·전체 그래프 수정

2026-11-07 · 사용자 수정 요청 반영 · Figma 디자인, 제품 구현 전

## 현재 요구

- 비교는 문단 전체 대신 바뀐 낱말·구절을 강조한다.
- 병합은 Docsa처럼 원문·가운데 편집 결과·수정본을 함께 보며 변경 구절을 선택하는 구성으로 한다.
- 전체 그래프는 작은 원형 노드를 유지하면서 연결선과 기록 이름을 정돈한다. 별도 모달 대신 사이드바를 넓히는 원칙을 유지한다.
- 고객의 개인 AI를 JaNovel 웹서비스 안에서 채팅으로 사용하는 것은 필수 요구다. 중간 MCP 서버는 실행·자료 연결의 검토 후보이며 이번 디자인 수정에서 서버를 구현하지 않았다.

## 원본에서 확인한 것

원본 `Docsa_FE`는 읽기만 했다.

- `DocumentCompareView.tsx`: 블록 대응 관계를 정렬하고, `diff_main`·`diff_cleanupSemantic`으로 텍스트 내부의 공통 구간과 변경 구간을 구분한다. 여기서 키워드 비교는 주요어를 AI로 추출하는 기능이 아니라 변경된 낱말·구절을 표시한다는 뜻이다.
- `editor-preview/diffRender.tsx`: 변경 구간을 인라인으로 렌더링한다. 병합에서는 해당 구간 선택을 처리한다.
- `DocumentMergeView.tsx`: 왼쪽 원문·가운데 편집 가능한 병합 결과·오른쪽 수정본, 전체 반영과 변경 구절 반영, 결과 직접 수정과 확대 보기를 제공한다. 이번에는 문단 선택 후 별도 결과 페이지로 넘어가던 시안을 이 3열 구조로 바꿨다.
- `DocumentGraph.tsx`·`useGraphData.ts`·`graphUtils.ts`: 브랜치·부모 관계를 배치하고 React Flow에서 이동·확대를 제공한다. 원본의 큰 카드·다색·그라데이션을 그대로 복제하지는 않았다. JaNovel의 기존 원형 노드·무채색·파란 포인트 결정을 유지했다.

원본 앱을 실행해 클릭 검증하거나 성능을 측정한 것은 아니다. 비교·병합 코드를 새 프로젝트로 가져오거나 수정하지 않았다.

병합 중앙에는 1358px을 사용하고, 내부 3열은 423·462·423px과 1px 구분선 두 개로 배치했다. 가운데 결과의 폭을 조금 더 준다. 채팅은 별도 서비스로 이동하는 의미가 아니라 같은 웹서비스의 접힌 패널 상태다. 비교·작성 화면에서는 기존 채팅 패널을 유지한다.

이전 ‘병합 결과 확인’ 프레임 `37:569`는 별도 단계가 필요 없어 제거했다. 분기 입력창 `37:312`는 유지했다. 병합 결과 확정 명칭은 ‘병합 스냅샷’이다. 원본 두 버전은 남고 새로운 결과를 기록하는 규칙을 유지한다.

## 확인과 한계

세 화면을 Figma에서 내보내 확인했다. 키워드 강조가 문단 전체를 덮지 않고, 전체 그래프의 분기·병합 선과 이름이 분리되며, 3열 병합이 화면 폭 안에 들어가는 것을 확인했다. 세 화면의 텍스트는 모두 Noto Sans KR이고 이미지 채우기는 0개다. 편집 가능한 레이어·텍스트·인스턴스로 구성했다.

이 결과는 디자인 상태다. 구절 선택 클릭·직접 편집·스냅샷 생성·패널 재개를 실제 애플리케이션에 구현하지 않았고 새 프로토타입 전환 전체도 검증하지 않았다. 예시는 의미 있는 변경 구절을 수동으로 배치한 것이며 Figma 안에서 diff 알고리즘이 실행되는 것은 아니다. 구현 시 Docsa의 실제 diff·선택 로직을 문항별 텍스트에 맞게 재사용하는 검토가 필요하다.

기존 로컬 HTML 시안과 `branch-review.html`·`merge-review.html`은 앞선 문단 선택 시안이다. 이번 구절 단위 Figma를 동작으로 검증한 결과로 안내하지 않는다. 최신 디자인 판단은 이 문서와 Figma를 기준으로 한다. 작업·검사 기록은 `_workspace/2026-11-06-figma/docsa-keyword-revision-result.json`에 남긴다.
