# 작성본·스냅샷 API 설계

문항마다 버전이 여러 개 있다. 버전마다 스냅샷(그 시점 본문을 고정한 기록)이 쌓이고, 맨 끝에 계속 고쳐 쓰는 초안이 하나 있다. 프론트는 이 이력을 브라우저에만 저장하므로 서버에 같은 구조와 규칙을 둔다. 지금 동작은 [버전 모델](../../frontend/src/model.js) · [버전 만들기·조합](../../frontend/src/writing-options.js) · [삭제 규칙](../../frontend/src/history-actions.js)을 따른다.

## 확정한 것

| 항목 | 결정 |
|---|---|
| 규칙 위치 | 서버가 검사한다. 문항 전체를 JSON으로 저장하지 않고 "스냅샷 남기기", "버전 삭제"처럼 동작마다 API를 둔다. 삭제·재연결 규칙이 깨지지 않고 여러 기기에서 같은 이력을 본다. |
| 조합 | 두 본문을 조합하면 독립된 새 버전과 첫 스냅샷을 만든다. 출처 버전과 연결하지 않고 출처 본문도 저장하지 않는다. 작성 화면의 "참고한 버전" 보기는 프론트를 연결할 때 없앤다. 출처를 스냅샷으로 고정해 연결하는 방식은 작성 중 초안을 쓸 때 원래 버전에 원하지 않은 스냅샷이 생겨 쓰지 않았다. |
| 초안의 기준 스냅샷 | 하나만 둔다. 프론트는 여러 개를 허용하지만 조합 스냅샷을 지운 뒤에만 생긴다. 기준 스냅샷을 지우면 같은 버전의 바로 앞 스냅샷이 기준이 된다. |
| 두 탭 충돌 | 초안에 저장 번호 `revision`을 둔다. 초안 저장과 스냅샷 생성 요청에 보던 번호를 함께 보내고 서버 번호와 다르면 `409 DRAFT_CONFLICT`와 최신 초안 `currentDraft`를 돌려준다. 프론트는 내 본문 유지와 서버 본문 받기 중에서 고르게 한다. |
| 초안 자동 저장 | 입력을 멈추고 1초 뒤와 화면을 떠날 때 저장한다. 실패하면 본문을 화면과 로컬에 두고 "저장 안 됨 · 다시 시도"를 보인다. 저장 시점과 실패 표시는 프론트 연결 때 만든다. |
| 제출본 | 문항당 하나다. 지정할 때 본문을 복사하고 어느 스냅샷이나 버전 초안에서 가져왔는지와 표시 이름을 남긴다. 프론트도 제출 이력 중 마지막 것만 쓴다. |
| 옛 스냅샷 편집 | 프론트가 API를 조합한다. 버전의 마지막 스냅샷이면 그 버전 초안을 저장하고, 옛 스냅샷이면 그 스냅샷에서 새 버전을 만든 뒤 초안을 저장한다. 되돌려 같아지면 프론트가 그 버전을 지운다. |

## 스키마

배포 전이므로 [V1](../../backend/src/main/resources/db/migration/V1__initial_schema.sql)을 고친다. [DBML](posting-reference-proposal.dbml)도 맞춘다.

- `writing_versions`: `description`, `position`(문항 안 순번, 유니크), `created_at`, `from_snapshot_id`(갈라진 스냅샷), `base_snapshot_id`(초안 기준), `draft_updated_at`, `draft_revision`을 더한다. 두 스냅샷 참조는 같은 문항의 스냅샷만 가리키고, 스냅샷이 지워지면 비운다.
- `snapshots`: `number`(문항 안 순번, 유니크)를 더한다. 스냅샷을 지워도 다른 번호는 바뀌지 않는다. 화면에는 번호 대신 스냅샷 이름을 보이고, 이름을 비우면 프론트와 같은 `스냅샷 N`을 저장한다.
- `snapshot_parents`: 같은 버전 안의 앞 스냅샷과, 갈라진 버전의 첫 스냅샷이 시작한 스냅샷을 연결한다.
- `essay_questions`: `active_version_id`(마지막으로 연 버전)를 더한다.
- `submission_answers`: `source_snapshot_id`, `source_version_id`, `label`을 더한다.
- 문항을 만들 때 "기본" 버전을 함께 만들고 현재 버전으로 지정한다.

## API

소유권은 문항→지원 건→사용자로 확인하고 다른 사용자의 이력은 `404`로 응답한다.

| 동작 | 경로 | 주요 오류 |
|---|---|---|
| 이력 전체 조회 (버전·초안·스냅샷·제출본·현재 버전) | `GET /api/questions/{qid}/writing` | `404` |
| 초안 저장 `{body, revision}` | `PUT /api/versions/{vid}/draft` | `409 DRAFT_CONFLICT` |
| 스냅샷 남기기 `{body, revision, title?, description?}` | `POST /api/versions/{vid}/snapshots` | `400 EMPTY_TEXT`, `409 NO_CHANGES`·`DRAFT_CONFLICT` |
| 스냅샷 이름·설명 수정 `{title?, description?}` → `{id, title, description}` | `PATCH /api/snapshots/{sid}` | `404 SNAPSHOT_NOT_FOUND` |
| 스냅샷 삭제 (버전의 마지막이고 다른 기록·버전이 참조하지 않을 때) | `DELETE /api/snapshots/{sid}` | `409 SNAPSHOT_IN_USE` |
| 새 버전 (빈 버전 또는 스냅샷에서 시작) `{name?, description?, fromSnapshotId?}` | `POST /api/questions/{qid}/versions` | `400 SNAPSHOT_MISMATCH`, `409 DUPLICATE_VERSION_NAME` |
| 버전 이름·설명 수정 `{name?, description?}` → `{id, name, description}` | `PATCH /api/versions/{vid}` | `404 VERSION_NOT_FOUND`, `409 DUPLICATE_VERSION_NAME` |
| 버전 삭제 (그 버전 스냅샷을 부모로 둔 기록은 남은 조상으로 다시 잇는다) | `DELETE /api/versions/{vid}` | `409 LAST_VERSION` |
| 조합 `{body, name, description?}` | `POST /api/questions/{qid}/combinations` | `400 EMPTY_TEXT` |
| 현재 버전 지정 | `PUT /api/questions/{qid}/active-version` | |
| 제출본 지정·교체·직접 수정, 해제 | `PUT`·`DELETE /api/questions/{qid}/submission` | |

초안을 저장하면 갱신된 초안을 돌려준다. 스냅샷을 남기면 `201`과 함께 새 `snapshot`과 갱신된 `draft`를 돌려준다. 둘 다 성공할 때마다 초안의 저장 번호가 1 증가한다. 새 스냅샷은 초안의 기준이 되며, 이전 기준이 있으면 부모로 연결된다. 본문은 문항에 설정할 수 있는 최대 길이인 100,000자까지 저장한다.

버전과 스냅샷 관리 규칙은 프론트와 같다.

- **새 버전:** 맨 뒤에 붙고 현재 버전이 된다. 입력한 이름이 같은 문항의 다른 버전과 같으면 번호를 붙이지 않고 `409 DUPLICATE_VERSION_NAME`으로 거절하고, 프론트는 입력 창에 알린다. 이름을 비우면 기본 이름 `새 버전`, 스냅샷에서 갈라지면 `<스냅샷 이름>에서 시작`을 쓰고, 기본 이름끼리 겹치면 앞 90자만 남긴 뒤 ` 2`, ` 3`을 붙인다. 사용자가 입력하지 않은 이름이라 거절하지 않는다. 스냅샷 이름은 겹쳐도 된다. 스냅샷에서 갈라지면 그 본문이 초안이 되고 시작 스냅샷이 초안의 기준이 된다.
- **이름·설명 수정:** 버전 이름을 비우면 지금 이름을 그대로 둔다. 스냅샷 이름을 비우면 `스냅샷 N`으로 돌아가고, 설명은 비우면 지운다. 프론트 `trim()`처럼 줄바꿈 없는 공백도 공백으로 본다. 스냅샷 본문은 바꿀 수 없다. 두 수정은 초안·스냅샷을 바꾸지 않으므로 읽지 않고 최종 이름·설명만 돌려준다.
- **버전 삭제:** 마지막 버전은 지울 수 없다. 다른 스냅샷의 부모나 다른 버전의 시작·기준이 지운 스냅샷이면, 지운 스냅샷을 건너뛰며 부모를 따라 올라가 처음 만나는 남는 스냅샷으로 다시 잇는다. 현재 버전을 지우면 남은 첫 버전이 현재 버전이 된다.
- **스냅샷 삭제:** 버전의 마지막 스냅샷이고, 그 스냅샷을 부모로 둔 스냅샷이나 시작·기준으로 쓰는 다른 버전이 없을 때만 지운다. 초안의 기준이었으면 지운 스냅샷의 부모가 기준이 된다. 다른 스냅샷 번호는 그대로다.
- **기준이 바뀜 때의 저장 번호:** 두 삭제로 어느 버전의 초안 기준이 바뀌면 본문은 그대로 두고 그 버전의 `revision`을 올린다. 이전 기준을 보던 화면의 저장과 스냅샷 요청은 `409 DRAFT_CONFLICT`로 거절된다.
- 두 삭제는 다시 이어진 결과를 반영한 작성 이력 전체를 `200`으로 돌려준다. 프론트는 이 응답으로 화면을 바꾼다.

## 구현 순서

단계마다 MockMvc 테스트로 성공, 규칙 위반과 다른 사용자 차단을 확인한다.

1. 스키마·엔티티, 문항 생성 시 기본 버전 — 완료
2. 이력 조회, 초안 저장, 스냅샷 남기기 — 완료
3. 버전 만들기·수정·삭제와 스냅샷 수정·삭제 — 완료
4. 조합
5. 제출본과 현재 버전

## 프론트 연결 때 할 일

- 초안 자동 저장 시점, 저장 실패 표시, 충돌 선택 화면
- "참고한 버전" 보기 제거
- 지원 건 수정 API에도 버전 번호로 충돌 방지([제품 기획](01-product-plan.md#개발-순서와-완료-확인))
