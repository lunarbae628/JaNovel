JaNovel은 공고, 자소서 수정 이력, 제출본, 일정과 면접 준비를 지원 건별로 관리한다. 핵심은 **자소서에서 무엇이 바뀌었는지 빠르게 확인하고, 제출할 답변을 면접에 다시 쓰는 것**이다. 첫 사용자는 여러 공고에 지원하며 자소서를 반복해서 수정하는 본인이다. [프론트 실행](../../frontend/README.md) · [백엔드 실행](../../backend/README.md) · [Figma 참고 화면](../design/27-frontend-handoff-review.md)

## 현재 구현

React 미리보기가 동작한다. 지원 건과 자소서 문항은 브라우저에 두고 서버와 동기화하며, 작성 이력·일정·제출본·면접 기록은 아직 브라우저에만 저장한다. 백엔드는 PostgreSQL에 Flyway 초기 마이그레이션 하나를 적용하고, 테이블 11개를 Java JPA 엔티티에 매핑했다. 공개 공고에서 읽은 본문과 첨부 이미지를 GPT-5.4 mini로 구조화한다. 지원 건 등록·조회·수정·삭제와 자소서 문항 관리 API가 있고, 작성 이력 API의 프론트 연결과 서버 인증은 다음 단계다. ### 공고와 지원 현황

- 공개 공고 링크를 가져오면 읽을 수 있는 회사·직무·마감일과 공고 항목을 확인 화면에 채운다. HTML에서 본문을 못 읽으면 브라우저로 렌더링한다. 이미지로 게시된 본문은 나눠서 같은 모델에 전달한다. 모집 직무가 여러 개면 지원할 직무를 고르고, 부족한 내용은 원문을 보며 직접 입력할 수 있다. 확인 화면에서 회사·직무·마감일과 선택 시각, 공고 항목, 채용 단계와 문항별 글자 수를 수정한다. 주요 업무·지원 요건·우대 사항 같은 공고 항목은 제목과 본문을 자유롭게 정해 추가·수정·삭제·재정렬한다.
- 목록에서 공고별 단계와 최종 합격·불합격·지원 취소를 선택하고 현황을 필터링한다. 사용자 정의 결과 옵션과 종료 당시 전형 단계는 DB 스키마에 반영했다. 화면과 서버 연동은 다음 단계다. [공고 등록](../../frontend/src/pages/Posting.jsx) · [지원 현황](../../frontend/src/pages/Applications.jsx)

### 자소서·버전·제출본

- 지원 목록이나 자소서 작성 화면에서 내 공통 자소서를 열어 문항과 초안을 작성한다. 문항이 없는 공고를 등록할 때 해당 지원 건으로 복사할 수 있다.
- 문항마다 독립 버전, 자동 저장되는 초안과 스냅샷을 관리한다. 스냅샷은 저장 시점의 답변 전문이며 이름·설명은 정보 버튼에서 확인한다. 저장한 본문을 편집하면 같은 버전의 초안에 반영한다. 수정 중인 초안이 있을 때는 충돌을 알리고 새 버전으로 작성할 수 있게 한다.
- 버전별 초안과 스냅샷 중 두 기록을 선택해 비교한다. 두 본문은 비슷한 문단끼리 맞춰 비교한다. 차이는 오른쪽 작성 중 본문에만 파랗게 표시하고, 그 본문을 편집하면 표시도 함께 갱신한다. 왼쪽 참고 본문은 표시 없는 전문을 보는 전체 탭과, 달라진 문장을 지금 문장과 참고 문장 한 쌍의 카드로 보여 주는 부분 탭으로 본다. 카드를 누르면 그 문장을 반영하고 다시 누르면 취소하며, 일괄 반영으로 한 번에 바꿀 수 있다. 또는 두 본문을 조합해 독립된 새 버전과 첫 스냅샷을 만든다. 전체 그래프에서 조합에 참고한 버전과 당시 본문을 볼 수 있다. 개별 스냅샷은 해당 버전의 마지막 기록이고 다른 기록이나 버전의 참조가 없을 때 삭제할 수 있다. 버전은 하나 이상 남기며, 버전을 삭제할 때 이어질 수 있는 이력은 남은 조상으로 연결한다. 조합 버전은 복사한 출처 본문을 보존한다. [작성 화면](../../frontend/src/pages/Editor.jsx) · [버전과 조합](../../frontend/src/writing-options.js) · [삭제 규칙](../../frontend/src/history-actions.js)
- 작성 화면의 별로 문항별 제출본을 지정한다. **제출본** 버튼으로 같은 지원 건의 모든 문항을 보고, 지정된 문항에서 **제출본 수정**으로 본문을 고치거나 확인 후 교체한다. 원본 버전을 고쳐도 지정한 답변 본문은 유지된다. 전체 제출본과 현재 문항을 각각 미리보거나 브라우저 인쇄 메뉴로 PDF 저장할 수 있다. 작성 화면의 **면접 연습**에서 지정된 제출본을 재사용한다. [PDF](../../frontend/src/components/EssayPdf.jsx) · [제출본 모델](../../frontend/src/model.js)

### 캘린더와 할 일

- 개인 일정·체크리스트와 지원 건의 마감·면접 등 일정을 한 달력에 표시한다. 빈 날짜를 더블클릭하거나 날짜 범위를 드래그해 추가하고, 일정이나 달력 아래 선택 날짜 목록에서 수정·삭제한다. 일정에는 제목, 기간·시간, 메모와 색상 등을 지정한다. 색상 범례는 생략한다.
- 기간 일정은 종료 날짜를 포함한다. 같은 요일 열을 위아래로 드래그하면 매주 반복 일정으로 열리고 드래그의 마지막 날짜를 종료일에 채운다. 매일 또는 매주 반복은 종료일까지 이어지며 종료일을 비우면 계속 반복한다. 특정 날짜만 수정하거나 건너뛰기, 전체 반복 수정, 체크리스트 회차별 완료·취소를 지원한다. 지원 마감 일정의 삭제는 해당 지원 건의 마감일·시각을 비운다. [일정 화면](../../frontend/src/pages/Schedule.jsx) · [반복 규칙](../../frontend/src/schedule.js)

### 면접 준비와 모의면접

- 지원 건별로 예상 질문과 텍스트 답변을 관리한다. 질문을 고르면 같은 화면에서 본문을 바꾸며 질문마다 녹음을 남겨 다시 듣거나 교체·삭제할 수 있다.
- 모의면접은 **예상 질문 연습**과 **자료 기반 연습**으로 나뉜다. 자료 기반 연습은 지정 제출본, 붙여넣은 이력서·포트폴리오·자소서 본문, 텍스트를 읽을 수 있는 PDF·TXT·MD에서 브라우저 규칙으로 질문을 만든다. 질문에 인용된 부분은 연습 기록에 남는다. 음성 합성이 질문을 읽을 때만 남색 입자 구가 움직인다. 듣기·일시정지·다음 질문·종료를 질문 옆에 모았고 연습한 질문과 진행 시간을 기록한다. 실제 답변 인식·AI 꼬리 질문과 전사는 AI 음성 연결 계획에 속한다. ### 친구·커뮤니티·수신함

- **친구** 화면 왼쪽에서 예시 계정을 검색·추가하고, 오른쪽에서 친구 캘린더 또는 채팅을 사용한다. 이메일 초대는 브라우저에 대기 상태로 표시한다. 친구의 일정과 할 일 상태를 보고 댓글을 남긴다. 수신함은 사이드바에서 모달로 열며 읽지 않음 보기, 모두 읽음, 예시 친구 요청 수락·거절, 채팅·일정 바로가기를 지원한다.
- **커뮤니티**는 자유·질문·스터디 모집·합격 후기 말머리의 게시판이다. 목록은 제목을 먼저 보여주고 작성자·날짜는 보조 정보로 표시한다. 별도 글쓰기 화면, 상세·댓글과 예시 스터디 참여 신청을 지원한다. 친구·대화·게시판 입력은 로컬 미리보기에서 유지된다. [친구](../../frontend/src/pages/Social.jsx) · [수신함](../../frontend/src/pages/Inbox.jsx) · [게시판](../../frontend/src/pages/Community.jsx)

## 확정한 제품 계획

### 공고 수집과 지원 상태

- 공고의 URL·이미지·텍스트 원문과 사용자가 확인한 입력값을 함께 보관한다. 자동으로 채운 항목은 사용자가 확인·수정하게 한다. 대표 마감 방식은 날짜 지정·수시채용·채용 시 마감·상시 접수 중 하나로 관리한다. 미입력은 `NULL`로 저장한다. 수시채용도 공고에 명시된 마감일·시각을 함께 저장할 수 있으며, 공고에 없는 마감 시각이나 전형은 비워 둔다.
- 공통 진행 상태는 관심·작성 중·제출·전형 진행·종료로 관리한다. 현재 전형은 해당 지원 건의 채용 단계에서 고르고, 전형 순서나 일정만으로 통과·제출을 확정하지 않는다. 종료 당시 결과 옵션과 단계 이름을 남긴다.
- 기본 결과는 최종 합격·불합격·지원 취소다. 사용자가 결과를 추가·수정·삭제하고 이름·색·순서를 정할 수 있게 한다. 결과 옵션은 사용자 단위로 관리해 여러 지원 건에서 재사용한다. 옵션을 비활성화해도 과거 지원 결과에 표시한다.

### 자소서와 제출본

- 지원 건과 문항 단위로 작성 공간을 분리한다. 기존 문항은 등록 순서를 유지한다. 자동 저장은 버전의 현재 초안을 갱신하고, 스냅샷에는 그 시점의 답변 전문을 고정한다. 복원·편집에서도 저장된 원본을 보존한다. 비교·조합은 구절 단위로 진행하며 결과는 새 버전의 첫 기록으로 남긴다.
- 조합 결과는 출처 버전과 연결하지 않는 독립된 새 버전과 첫 스냅샷이며 출처 본문은 따로 저장하지 않는다. 스냅샷에서 갈라진 버전은 시작 스냅샷을 잇고, 버전을 지우면 그 버전 스냅샷을 부모로 둔 기록을 남은 조상으로 다시 잇는다. 서버 API와 스키마는 [작성본·스냅샷 API 설계](12-writing-history-api.md)를 따른다.
- 문항당 현재 제출본 하나를 둔다. 지정할 때 답변을 복사하고, 그 본문을 따로 수정하거나 다른 버전으로 교체할 수 있게 한다. PDF와 자료 기반 면접은 같은 데이터를 읽는다. PDF에는 회사·직무·문항·답변을 출력하고 한글과 긴 답변의 페이지 분할을 검증한다. 실제 지원 사이트 접수는 사용자가 진행한다.

### 일정과 개인 할 일

- 개인 일정은 지원 건 없이 만들 수 있고, 체크리스트 완료와 지원 단계는 독립적이다. 기간·선택 시각·종일·색상과 반복 일정을 유지한다. 반복 유형을 바꿔도 지정한 종료일을 유지한다. 종료일이나 종료 시각이 시작보다 빠르면 입력을 보존하고 조건을 안내한다. 회차 편집과 전체 수정에서 기존 완료 이력을 보호한다.
- 주·월 경계에서 기간을 나눠 표시하되 하나의 일정으로 수정한다. 마감·면접·과제 일정은 해당 지원 건에 연결한다. 전형 순서를 다시 고쳐도 기존 일정과 단계 이동 기록의 연결을 유지한다. 날짜가 미정인 일정도 확인할 수 있게 한다.

### AI 피드백과 개인 맥락

- AI는 JaNovel 웹 채팅에서 쓴다. 기본은 JaNovel이 AI API로 제공하는 **JaNovel AI**(구독)다. 공고·문항·버전·제출본과 개인 맥락을 근거로 자소서 초안을 쓰고 첨삭·피드백한다. 선택으로 **기기 연결**을 둔다. 사용자 PC의 Codex·Claude Code가 JaNovel 웹 채팅에 응답하며, Sign in with ChatGPT가 승인되면 같은 갈래에 추가한다. ChatGPT·Claude 웹에서 JaNovel MCP로 첨삭하는 경로는 대화가 JaNovel 밖에 남아 쓰지 않는다. 로컬에서는 예시 응답으로 작성 흐름을 확인하고, 실제 호출을 켜서 초안 품질을 검증한다. [AI 방향과 연결](05-local-agent-chat-review.md)
- **개인 맥락.** JaNovel이 사용자의 경험·프로젝트·학력·기술·자격증·수상, 문체 선호와 희망 직무를 보관하고, 지원 건·문항·버전·제출본, 지원 결과와 채택한 수정 후보로 쓸수록 늘린다. 사용자가 확인한 사실만 근거로 쓰고, 채팅에서 새로 나온 경험·수치는 확인 대기로 둔다. 사용자는 내 맥락 화면에서 맥락을 보고 고치고 지우고 내보낸다. 공개 전에 수집 동의와 탈퇴 시 삭제를 갖춘다.
- **맥락 가져오기(선택).** 가입 뒤 초기 설정에서 사용자가 쓰던 ChatGPT·Claude가 기억하는 경험을 가져오도록 제안하고, 건너뛰거나 나중에 할 수 있다. MCP를 연결한 사용자는 AI가 직접 보내고, 연결하지 않았거나 MCP를 쓸 수 없는 사용자는 JaNovel이 준 프롬프트의 결과를 붙여 넣는다. 경력 관련 분류로만 받고, 항목별 미리보기에서 사용자가 남긴 항목만 저장하며 기간·수치가 있는 항목을 강조한다. 붙여넣기는 고른 항목만 서버로 보내고, MCP는 받은 내용을 임시 공간에 두었다가 빼거나 고르지 않은 항목을 지운다. MCP 방식으로 두 AI의 기억을 가져온 실험에서 44건이 모두 맞았다. [가져오기 실험](11-ai-experiments.md#a1-mcp-맥락-가져오기)
- **내 AI에서 JaNovel 쓰기(MCP).** 사용자가 ChatGPT·Claude에 JaNovel MCP를 연결하면 쓰던 AI 대화에서 맥락 가져오기, 공고 등록, 일정 추가를 한다. 공고는 사용자 AI가 웹 등록과 같은 형식으로 정리해 채팅에서 확인받은 뒤 지원 건으로 바로 만들고, 공고와 일정 모두 'AI가 추가함'으로 표시해 웹에서 고치게 한다. MCP는 추가만 열고 수정·삭제와 자소서 본문·개인 맥락 읽기는 열지 않는다. 초안과 첨삭은 JaNovel AI에 둔다. 배포와 OAuth 뒤 열고, ChatGPT 일반 사용자에게는 플러그인 게시 뒤 제공한다. [JaNovel MCP](05-local-agent-chat-review.md#내-ai에서-janovel-쓰기-mcp)
- 피드백과 초안에는 원본 답변의 식별자, 평가 기준 버전, 대상 구절, 이유·근거와 근거 출처를 기록한다. 실제 경험과 본인 기여, 문항·직무 적합성, 문장 품질의 세 기준을 평가하며 근거가 부족하면 사용자에게 확인을 요청한다. 초안과 수정안은 후보로 저장하고, 비교 후 사용자가 채택할 때 새 기록에 반영한다. 원본이 바뀌었으면 다시 비교하고, 재시도는 결과 중복을 방지한다.

### 1인 AI 음성 모의면접

- 예상 질문·답변·질문별 녹음은 면접 준비 화면에 둔다. AI 모의면접은 등록한 질문으로 시작하는 **예상 질문 연습**과 사용자가 고른 제출본·이력서·포트폴리오에서 질문을 만드는 **자료 기반 연습**을 유지한다. 질문이 참고한 문항이나 자료를 표시한다. 제출본이 없을 때 현재 작성본을 쓸지는 사용자가 선택한다.
- **AI 음성 API를 연결한다.** 질문 읽기, 마이크 답변 인식, 답변 기반 꼬리 질문, 일시정지·재개, 종료 후 전사·질문별 피드백을 제공한다. 타이핑 답변 기록은 예상 질문 화면에서 다룬다. 질문할 때만 입자 구를 움직이고, 현재 질문 가까이에 종료와 진행 제어를 둔다. 준비 메모, 질문별 녹음, 연습 전사와 제출본은 각각 보관한다. 질문별 녹음 교체는 새 파일 저장이 끝난 뒤 적용한다.
- 마이크 권한 거절, 답변 인식 중단, 재연결·종료와 저장 실패 때의 행동을 정한다. 피드백은 빠진 근거, 불명확한 역할과 설명하지 못한 기술 선택을 짚는다. 음성 제공자와 원음 저장·보관 정책, 한국어 인식 품질·응답 지연·회차당 비용은 실제 연결 실험에서 확인한다.

### 친구와 커뮤니티의 서버 연동

- 친구 검색·요청·수락, 채팅, 캘린더 일정 댓글과 수신함을 실제 계정에 연결한다. 친구 캘린더는 기본 비공개이며, 사용자가 고른 일정·할 일의 상태를 친구가 본다. 회사·직무와 메모의 공개 범위도 선택하고, 공유를 철회하거나 친구 관계를 해제하면 이후 조회 권한에 반영한다.
- 모집 글은 목적·일정·인원·조건을 받고 모집자가 신청과 마감 상태를 관리한다. 참가한 스터디는 일정과 채팅에서 준비를 이어간다. 합격 후기는 작성자가 공개할 회사·직무·전형과 준비 방법을 선택한다. 댓글과 알림은 작성자 및 대상의 읽기 권한을 확인한다.

### 장기 계획 · 친구와 AI가 함께하는 다인 면접

기존 JaNovel 기능 이후 착수한다. 회사별 면접 준비에서 진입하고, 고른 공고·제출본·예상 질문을 연습에 가져온다. 방의 설정 공개 범위와 참가자 개인 자료 접근은 각각 정한다.

1. **방 설정.** 일대일·일대다·다대일·다대다 유형이나 지원자·면접관 수를 정한다. 공통·지정 질문, 기출, 분위기, 면접 길이와 답변 제한 시간을 입력한다. 사용자 입력과 AI가 보완한 설정을 표시하고, 정보가 적으면 기본 조건부터 시작할 수 있게 한다.
2. **대기실.** 혼자 들어가거나 친구를 링크로 초대한다. 사람에게 지원자·면접관 역할을 배정하고 남은 자리에 AI를 배치한다.
3. **진행.** 좌석, 발화자, 마이크와 타이머를 보인다. 공통 질문은 순서대로 진행하고 개별 지목과 꼬리 질문을 지원한다. 사람과 AI가 지정된 차례에 답한다. 참가자 화면의 진행 상태와 발언 순서를 맞추고 연결이 끊긴 사람의 복귀를 검증한다.
4. **복기.** 질문·답변·내 꼬리 질문·발화 시간과 다시 연습할 질문을 확인한다. 참가자별 복기 자료의 공개 범위를 정하고 같은 조건 또는 바꾼 조건으로 다시 연습한다.

### 화면과 접근성 기준

- 공고 등록·면접 추가·글쓰기·친구 추가를 해당 작업 가까이에 배치한다. 목록과 작성 화면은 공통 드롭다운과 키보드 조작을 기준으로 맞춘다. 친구 채팅, 친구 캘린더와 게시판은 긴 글과 좁은 화면에서도 읽기 흐름을 검증한다.
- 화면에서 선택한 지원 건·문항·버전은 돌아오거나 비교 화면을 열 때 유지한다. 빈 상태, 저장 실패와 재시도, 마이크 권한 및 연결 실패 상태를 확인한다.

## 설계 선택과 미결 항목

### 백엔드와 데이터 모델

첫 버전은 **Java 21·Spring Boot 모듈러 모놀리스와 PostgreSQL 단일 DB**로 시작한다. 공고 항목·채용 단계·자소서 문항은 지원 건 안에서 순번을 가진다. 초안은 버전에, 답변 전문은 스냅샷에 저장한다. [초기 마이그레이션](../../backend/src/main/resources/db/migration/V1__initial_schema.sql)

- **현재 전형과 순서.** 채용 단계 순번은 유니크 제약 검사를 트랜잭션 끝까지 미뤄 서로 교환할 수 있다. 복합 외래 키 `(id, current_stage_id) → (application_id, id)`는 지원 건이 자기 전형만 참조하게 한다. 현재 전형을 삭제하면 `ON DELETE SET NULL (current_stage_id)`로 선택만 비운다. [PostgreSQL 제약 검사 시점](https://www.postgresql.org/docs/18/sql-set-constraints.html) · [PostgreSQL 외래 키](https://www.postgresql.org/docs/18/ddl-constraints.html#DDL-CONSTRAINTS-FK)
- **결과 옵션.** 종료한 지원 건은 선택한 옵션 ID를 저장한다. 결과별 필터는 옵션 ID를 기준으로 한다. 비활성화할 때는 `archived_at`을 채우고 기존 참조를 보존한다. [초기 마이그레이션](../../backend/src/main/resources/db/migration/V1__initial_schema.sql)
- **자소서 이력.** `snapshot_parents`는 같은 문항 안에서 부모와 자식 스냅샷을 연결한다. `submission_answers`는 문항 ID를 기본 키로 사용해 문항당 현재 제출본 하나를 저장한다.
- **인증과 운영.** 사용자 이름은 필수다. 소셜 가입에서 제공자가 이름을 보내면 기본값으로 채우고, 이름이 없으면 가입을 완료하기 전에 입력받는다. 이메일·Google 로그인은 현재 화면의 후보 경로다. 인증·계정 연결과 비밀번호 재설정 정책을 구현 시 정한다. 실제 공개 전에는 사용자의 데이터 내보내기·삭제, 계정 간 권한 분리, HTTPS, 백업·복구를 확인한다.

### 먼저 검증할 후보와 보류 항목

- **AI 연결 기술.** JaNovel AI의 모델 제공자와 모델은 품질·지연·원가를 보고 정한다. JaNovel MCP(맥락 가져오기·공고 등록·일정 추가)는 배포와 OAuth를 갖춘 뒤 열고 ChatGPT 플러그인으로 게시한다. 기기 연결은 중계 서버와 Codex app-server·Claude Code Channels로 하며, 전용 폴더 밖의 파일 읽기·쓰기와 셸 실행을 설정으로 막을 수 있을 때만 연결한다. Channels는 연구 미리보기라 일반 공개 여부를 따로 정한다. Sign in with ChatGPT는 서비스 배포 뒤 관심 양식을 내고 승인되면 기기 연결 갈래에 추가한다. Claude Code를 대신 실행하는 방식과 사용자 API 키는 쓰지 않는다. 실험 순서는 [AI 방향과 연결](05-local-agent-chat-review.md#실험-목록)을 따른다. 음성 제공자·원음 정책과 다인 면접의 서비스명·도메인·저장·배포 분리는 미결이다.
- **개인 맥락 효과.** 개인 맥락이 초안과 피드백을 실제로 낫게 하는지, 확인되지 않은 사실이 섞이거나 다른 사용자에게 노출되지 않는지를 [개인 맥락 효과](02-critical-review.md#다른-사용자와-ai-평가) 시험으로 확인한다. 결과가 나쁘면 맥락을 쌓고 쓰는 규칙을 고친 뒤 다시 시험한다.
- **요금 구조.** 기본은 JaNovel AI 구독이다. 하루 몇 회 무료 사용을 후보로 두고, 한도와 요금은 문항당 원가와 유료 수요를 확인한 뒤 정한다. 기기 연결은 JaNovel 모델 비용이 들지 않으므로 무료로 둘지 구독에 넣을지 따로 정한다. 티오의 공개 요금(Free AI 일 5회, Lite 월 14,900원, Pro 월 19,900원)을 비교 기준으로 둔다. JaNovel AI도 초안을 쓰므로 티오와 기능이 겹친다. 차별점은 쓰던 AI에서 가져온 맥락으로 첫날부터 사용자를 아는 AI와, 수정 이력·제출 결과로 쌓이는 맥락에 둔다. [티오 비교](03-sources.md#티오와의-비교)
- **비용과 배포.** 개발 중에는 추가 지출을 피하는 초기 조건을 유지한다. 홈서버와 AWS는 배포 후보이며 HTTPS, 사용 가능한 자원·백업·복구와 운영 비용을 비교한다. 서비스 비용과 공고 추출·AI 피드백·음성의 사용량과 호출 비용을 각각 추정한다.
- **주간 공고 추천.** 후순위다. 기존 월요일 GPT 추천을 기준선으로 Java/Spring 적합성과 토스·네이버·카카오·LG CNS·삼성SDS의 관련 기회를 본다. 추천에 원문 링크·확인 시점·마감과 제외 조건을 표시하고 중복을 제거한다. 선택한 공고는 지원 건으로 이어지게 한다. 유료 추천과 방을 만든 사람이 회차권을 쓰고 초대받은 친구는 참가하는 과금 방식은 사용성·원가·지불 의사를 확인할 후보다. [추천 검증](02-critical-review.md)
- **초기 범위.** 작성은 문항별 텍스트에 집중한다. 범용 이력서 편집기, 자동 지원·합격 확률 점수, 전체 채용 사이트 자동 수집, 그래프 직접 편집·자동 병합, 외부 캘린더 동기화는 초기 범위 밖에 둔다. 경험 입력은 JaNovel AI의 내 맥락 화면으로 들어온다. 다른 지원 건으로 답변을 복제하는 경로를 도입하면 원래 글·이력·제출본이 유지되는지 함께 검증한다.

## 개발 순서와 완료 확인

1. **스키마와 지원 현황 API.** 초기 스키마와 JPA 매핑을 적용했고 지원 건 등록·조회·수정·삭제, 상태·현재 전형 변경, 공고 항목·전형 수정, 자소서 문항 추가·수정·삭제·순서 변경 API를 구현하고 프론트와 연결했다. 서버 계정 인증 연결 전에는 미리보기 접근 키로 사용자를 구분하며, 사용자별 접근 권한은 인증을 연결할 때 다시 검증한다. [API 문서](../../backend/README.md#api-문서)
2. **개인 기능.** 인증([인증 기획](10-authentication-plan.md)), 공고 원문·확인본, 문항 작성·비교·조합, 제출본, 기본 일정과 예상 질문 화면을 연결한다. 저장 실패에서 입력을 유지하고 사용자가 수정·재시도할 수 있는지 확인한다. 지원 건과 문항은 프론트와 연결했다. 서버는 `If-Match`로 받은 지원 건 버전이 최신 버전과 다르면 409를 반환한다. 프론트는 수정 요청에서 409를 받으면 해당 지원 건의 서버 저장을 멈추고 최신 내용 불러오기를 안내한다. 현재 미리보기의 지원 건 삭제 요청에는 버전을 보내지 않는다. 작성 이력(초안·스냅샷·조합·제출본)은 다음에 연결한다.
3. **AI와 개인 실사용.** JaNovel AI 채팅으로 실제 초안·첨삭 요청과 후보 저장·채택을 한 경로에서 검증한다. 개인 맥락과 내 맥락 화면, 붙여넣기 맥락 가져오기를 함께 만들고 개인 맥락 효과를 시험한다. JaNovel MCP와 기기 연결은 그 뒤 [실험 목록](05-local-agent-chat-review.md#실험-목록)을 따른다. 실제 지원 3건에서 변경점 확인·원문 보존·제출본 찾기 시간을 측정한다. [제품 검증 계획](02-critical-review.md)
4. **보조 기능.** 공고 자동 추출, 1인 AI 음성 모의면접과 친구·채팅·수신함·커뮤니티의 서버 기능을 순서대로 검증한다. 여러 사용자가 들어오기 전에 데이터 권한과 공유 철회를 시험한다.
5. **공개 전 보호 장치.** 아직 배포하지 않아 로컬에서만 쓰며, 공개하기 전에 세 가지를 갖춘다. 공고 추출 등 모델 호출 API에 로그인한 사용자만 접근하게 하는 인증, 사용자별 호출 횟수 제한, 큰 이미지 처리에서 서버가 메모리 부족으로 멈추지 않게 하는 메모리 한도와 동시 처리 수다. 호출 한 번에 모델 비용과 Chrome 자원이 들므로 부하 시험으로 한도를 정한다.
6. **다인 면접과 후속 제품 검증.** 사람과 AI가 참여하는 방에서 설정한 역할·발언 순서와 재연결을 확인한다. 추천의 착수와 JaNovel AI의 무료 한도·요금은 사용 결과와 운영비를 보고 결정한다.
