# 제품 검증 계획

2026-11-23 정리 · 2026-11-27 수정 · 실행 전 기준

공고와 자소서를 한곳에 모으는 것만으로 사용 가치가 입증되지는 않는다. 실제 지원에서 바뀐 구절, 확정한 제출본과 면접 자료를 얼마나 빠르고 정확하게 찾는지 확인한다. 경쟁 서비스의 공개 안내는 검증 질문을 만든 참고 자료다. [조사 근거](03-sources.md) · [제품 기획과 현재 구현](01-product-plan.md)

## 핵심 흐름 검증

| 시나리오 | 확인할 결과 |
| --- | --- |
| 공고·전형 | 출처에서 확인본을 다시 찾고 틀린 항목을 고칠 수 있다. 전형이 다른 두 지원 건을 등록하고 순번을 바꾸거나 현재 단계를 삭제해도 다른 지원 건과 일정은 유지된다. |
| 작성과 조합 | 자동 저장과 스냅샷 생성에서 실패 상태를 알리고 초안을 복구한다. 다른 문항·지원 건은 그대로다. 조합 도중 실패하면 결과와 부모 링크가 함께 롤백된다. 부모 삭제 뒤에도 자식 답변과 남은 링크를 확인한다. |
| 제출본·PDF | 원본 버전을 다시 편집해도 기존 제출본 본문이 유지된다. 같은 제출본을 화면·PDF·면접 연습에서 확인한다. 한글, 긴 답변, 지정하지 않은 문항과 출력 범위를 점검한다. |
| 일정 | 기간의 마지막 날짜가 포함된다. 반복 회차 수정·건너뛰기·완료를 다른 날짜와 구분하고, 개인 할 일 완료가 지원 단계를 바꾸지 않는지 확인한다. |
| 면접·권한 | 질문마다 텍스트·녹음·전사를 구분한다. 마이크 거절, 음성 연결 끊김·재개, 공유 범위 축소와 계정 간 접근 거부를 실제 조건에서 확인한다. |

## 개인 실사용

실제 지원 3건에서 평소 GPT·문서·캘린더 방식과 JaNovel을 비교한다.

| 작업 | 기록할 결과 |
| --- | --- |
| 공고와 문항 등록 | 소요 시간, 마감일이나 문항의 수정 횟수 |
| 글 수정과 비교 | 변경 구절을 찾는 시간, 이전 표현 복원과 원문 유실 여부 |
| 제출본 다시 찾기 | 지원 건과 문항에 맞는 답변을 찾는 시간, 선택 오류 |
| 일정·면접 준비 | 중복 일정 입력, 마감 누락, 제출본을 다시 옮겨 적는 수고 |

저장한 글이 유실되거나 지정한 제출본이 의도치 않게 바뀌면 이를 먼저 고친다. 등록 시간이 늘면 정보를 옮겨 적는 단계부터 줄인다.

## 다른 사용자와 AI 평가

- 개인 흐름을 검증한 뒤 비슷한 지원자 5명의 2주 사용을 제안한다. 설명 없이 두 번째 지원 건을 등록하고 비교·제출본 조회를 다시 하는지와 기존 방식으로 돌아간 이유를 기록한다. 5명 중 3명이 재사용하는 기준은 후속 검증을 위한 잠정 기준이다. 지원 활동이 없는 기간은 재사용을 해석할 때 구분한다.
- 같은 공고·문항·경험·초안에서 평소 AI 사용과 JaNovel 맥락·평가 기준을 넣은 결과를 비교한다. 사실·경험 보존, 문항·직무 적합성, 문장 품질을 보고 근거 없는 경험이나 수치를 만들면 실패로 기록한다. 첫 비교 목표는 10개 문항이다. 맥락을 수동 전달할 때와 연결 도구로 전달할 때의 설정 시간·실패·지연·비용도 따로 기록한다.
- **개인 맥락 효과.** JaNovel AI로 같은 문항의 초안과 첨삭을 개인 맥락을 넣었을 때와 넣지 않았을 때 비교한다. 효과는 확인된 사실을 정확히 다시 쓰는지와 사용할수록 사용자가 고치는 양이 줄어드는지로 본다. 안전은 세 가지로 본다. 확인되지 않은 경험·수치가 결과나 맥락에 들어가는지, 근거 출처를 표시하는지, 다른 계정이나 지원 건의 맥락이 노출되는지다. 확인되지 않은 사실이 쓰이거나 다른 계정의 맥락이 노출되면 실패로 보고, 규칙을 고친 뒤 다시 시험한다. 결과와 문항당 원가로 무료 한도와 요금을 정한다. ## 후속 추천 검증

주간 추천을 다시 검토할 때 기존 월요일 GPT 추천과 4주간 비교한다. 새로 발견한 적합 공고, 중복·마감 공고 비율, 실제 지원한 수와 목록을 검토한 시간을 기록한다. 관심 기업에 적합 공고가 없는 주도 포함한다. 시장성, 합격률 개선, 유료 수요와 실제 운영비는 검증 결과가 나온 뒤 판단한다.
