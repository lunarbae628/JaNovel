# JaNovel frontend

Figma 시안을 실제로 사용해 보는 독립 React 프론트입니다. 원본 Docsa 코드는 수정하지 않습니다.

## 실행

```sh
cd /Users/moon/Desktop/Works/job-application-service
npm --prefix frontend ci
npm --prefix frontend run dev
```

- 지원 현황: http://127.0.0.1:5173/#/applications
- 로그인: http://127.0.0.1:5173/#/login
- 로컬 미리보기라 로그인 없이 ‘둘러보기’로 진입할 수 있습니다.
- 같은 주소·브라우저에서 입력을 유지합니다. `localhost`와 `127.0.0.1`은 별도 저장 공간이므로 위 주소를 일관되게 쓰세요.

## 사용 흐름

1. 공고 등록 → 텍스트 붙여넣기 또는 링크·이미지 보관 → 회사·직무·문항·채용 절차 확인.
2. 문항 작성 → 스냅샷 이름·설명 기록 → 그래프 노드를 눌러 본문 보기.
3. ‘다른 안과 비교’ 또는 기록의 ‘작성 중과 비교’로 두 칸 비교를 엽니다. 왼쪽은 참고 기록, 오른쪽은 편집할 분기의 현재 초안입니다. 차이는 왼쪽에만 표시하며 달라진 구절을 누르면 그 부분만 오른쪽 초안에 반영됩니다. 오른쪽은 일반 편집칸으로 직접 고칠 수 있습니다. 스냅샷은 왼쪽에서 선택하며 원본은 바뀌지 않습니다.
4. 스냅샷 본문은 수정 버튼 없이 바로 입력할 수 있습니다. 최신 기록을 고치면 해당 분기의 작성 중이 생기고, 중간 기록을 고치면 자동 분기합니다. 원문과 정확히 같아지면 작성 중이 사라집니다. 아직 스냅샷이 없는 자동 분기는 함께 정리하며 명시적으로 만든 분기는 유지합니다. 기존 초안은 확인 없이 덮어쓰지 않습니다.
5. 분기 아이콘으로 이름·설명을 붙여 분기. 병합 화면에서 양쪽 전체 본문을 비교하고 변경 구절을 눌러 가운데 결과에 반영. 같은 구절을 다시 누르면 선택이 해제됩니다. 결과는 직접 편집할 수 있고, 병합하기에서 이름·설명·결과 위치(새 분기·기존 분기)를 선택합니다. 공통 구간은 기본으로 포함되며 변경 구절은 선택한 쪽만 포함됩니다.
6. 병합은 이름·설명을 가진 결과 스냅샷을 바로 남기고 그 본문으로 이동합니다. 오른쪽에서 가져온(from) 분기의 작성 중은 내용을 보존한 뒤 자동으로 닫습니다. 결과 본문을 실제로 수정하면 다시 작성 중이 생깁니다.
7. 피드백 요청은 공고·문항·본문·기준을 복사합니다. 외부 AI에서 받은 답변과 수정안을 ‘응답 추가’에 붙여넣으면 대화가 보관됩니다. ‘수정안 비교’는 같은 두 칸 비교 화면에서 열리며 필요한 구절만 현재 초안에 반영할 수 있습니다.
8. 지원 상세에서 일정·채용 절차·현재 단계 수정. 달력에서 일정을 선택해 상세로 이동.
9. 제출본 관리에서 문항별 버전을 골라 고정본을 만듭니다. 이후 초안 수정과 분리되며, 제출 완료 표시는 직접 바꿉니다. 지원 링크를 여는 것으로 제출 처리하지 않습니다.

기본 그래프는 스냅샷을 중심으로 표시하며 실제 변경이 있는 분기의 ‘작성 중’만 추가됩니다. 스냅샷 생성 후에는 작성 중 노드가 사라집니다. 기존 미저장 초안은 보존하며 재진입 시 이어 쓸 수 있습니다. 과거 기록을 선택해 읽기만 하면 분기나 초안을 만들지 않습니다.

그래프의 선·원에 분기별 색을 사용하고 버전 번호는 중립색으로 표시합니다. 선택은 노드 바깥 링과 행 배경으로 표시합니다. 기존 자동 배정 색도 새 팔레트로 표시하고 분기를 삭제해도 남은 분기의 색은 유지합니다. 주변 기록 / 펼친 기록형 / 지도형을 지원합니다. 양옆 접기·너비 드래그 및 키보드 화살표 조절이 가능합니다.

## 기록 정리

- 스냅샷 노드 선택 → 본문 옆 휴지통. 뒤에 이어진 스냅샷이나 다른 분기의 참조가 없는 끝 기록만 삭제할 수 있습니다. 삭제 확인창을 거치며 현재 초안 본문은 보존합니다.
- 그래프 상단 ‘분기 관리’ 아이콘 → 분기 옆 휴지통. 스냅샷·초안 삭제 개수와 복구 불가를 확인한 뒤 분기를 삭제합니다. 다른 분기의 본문·제출본은 보존하고, 삭제된 출처의 연결은 남은 조상으로 이어 줍니다. 마지막 분기 하나는 유지합니다.
- 수동 ‘작성 중 닫기’ 기능은 없습니다. 원문으로 되돌리거나 스냅샷으로 확정하면 작성 중이 사라집니다. 병합 원본의 자동 닫기는 유지합니다.

## 연결 상태

실제 서버 인증·Google/카카오 OAuth·메일 발송·공고 URL 수집·이미지 OCR·AI API/MCP는 아직 연결하지 않았습니다. 각 화면에 연결 전 상태를 표시합니다. 인증 화면은 전환·유효성 확인용이며 비밀번호는 저장하지 않습니다. 회원가입 화면의 미리보기 인증번호는 `123456`입니다.

주간 공고 추천·실시간 음성 면접은 후속 범위이며 이 프론트에 구현하지 않았습니다.

## 보관과 백업

- 문서·기록·일정·제출본: 이 브라우저의 localStorage (`janovel.frontend.v1`).
- 첨부 이미지: IndexedDB (`janovel-attachments`).
- 상단 백업에서 JSON 내보내기·검증 후 불러오기. JSON은 이미지 파일을 포함하지 않습니다.
- 저장 실패는 화면에 표시합니다. 손상된 기존 저장 데이터는 자동 덮어쓰기하지 않습니다.
- 브라우저 저장 공간 삭제·다른 기기로 이동 전에 백업하세요.

## 검증

```sh
npm --prefix frontend test
npm --prefix frontend run build
```

Node 모델 테스트는 불변 스냅샷, 자동 분기, 초안 충돌, 두 병합 방식, 그래프 부모 연결, 고정본 분리, 공고 문항 입력, 지연된 메시지의 최신 편집 보존, 백업 데이터 검증을 확인합니다. 두 칸 비교의 부분 반영·연속 클릭·반복 문구와 활성 초안 표시·보존도 검증합니다.

기록 정리 테스트는 끝 기록 삭제 제한, 다른 분기·병합 참조 보존, 활성·마지막 분기 삭제, 닫기·재편집, 빈 본문, 스냅샷 번호 중복과 반복 병합 그래프의 삭제 처리 시간을 확인합니다.
