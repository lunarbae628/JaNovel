# JaNovel frontend

Figma 시안을 실제로 사용해 보는 독립 React 프론트입니다. 원본 Docsa 코드는 수정하지 않습니다.

## 실행

```sh
cd /Users/moon/Desktop/Works/job-application-service
npm --prefix frontend ci
npm --prefix frontend run dev
```

- 지원 현황: http://127.0.0.1:5173/#/applications
- 로그인: http://127.0.0.1:5173/#/login
- 로컬 미리보기라 로그인 없이 ‘둘러보기’로 진입할 수 있습니다.
- 같은 주소·브라우저에서 입력을 유지합니다. `localhost`와 `127.0.0.1`은 별도 저장 공간이므로 위 주소를 일관되게 쓰세요.

## 사용 흐름

1. 공고 등록 → 텍스트 붙여넣기 또는 링크·이미지 보관 → 회사·직무·문항·채용 절차 확인.
2. 문항 아래에서 주제별 작성안을 추가합니다. 새 작성안은 빈 본문과 독립된 수정 기록으로 시작하며 이름·설명을 바꿀 수 있습니다.
3. 작성안 안에서 편집하고 스냅샷을 남깁니다. 과거 기록을 고쳐도 같은 작성안에 초안이 생기며 원본 스냅샷은 유지합니다. 기존 미저장 초안과 충돌하면 확인 없이 덮어쓰지 않습니다.
4. 비교 화면 양쪽에서 같은 작성안·다른 작성안의 스냅샷 또는 작성 중 본문을 선택합니다. 오른쪽이 작성 중일 때 구절을 가져오거나 직접 편집할 수 있고 스냅샷은 읽기 전용입니다. 비교 대상은 새로고침 후에도 유지합니다.
5. ‘합쳐서 새 작성안 만들기’에서 양쪽 구절을 선택하거나 전체 본문을 차례로 추가합니다. 가운데에서 연결 문장과 순서를 직접 다듬을 수 있습니다.
6. 결과는 독립된 새 작성안의 첫 스냅샷으로 남습니다. 원본 두 작성안의 초안·기록은 바뀌지 않으며, 참고한 두 본문을 고정해 출처 버튼으로 다시 볼 수 있습니다. 원본을 이후 수정·삭제해도 조합 당시의 출처 본문은 남습니다.
7. 피드백 요청은 공고·문항·본문·기준을 복사합니다. 외부 AI에서 받은 답변과 수정안을 ‘응답 추가’에 붙여넣으면 대화가 보관됩니다. ‘수정안 비교’는 같은 두 칸 비교 화면에서 열리며 필요한 구절만 현재 초안에 반영할 수 있습니다.
8. 지원 상세에서 일정·채용 절차·현재 단계 수정. 달력에서 일정을 선택해 상세로 이동.
9. 제출본 관리에서 문항별 버전을 골라 고정본을 만듭니다. 이후 초안 수정과 분리되며, 제출 완료 표시는 직접 바꿉니다. 지원 링크를 여는 것으로 제출 처리하지 않습니다.

왼쪽에는 작성안 목록과 선택한 작성안의 수정 기록을 표시합니다. 과거의 분기·병합 데이터도 ID와 본문을 보존해 작성안별로 표시합니다. 스냅샷 번호는 기존 링크·참조를 유지하기 위해 문항 전체 기준을 사용합니다. 작성안 색은 남색·초록·갈색의 차분한 팔레트이며 패널 접기·너비 조절은 유지합니다.

## 기록 정리

- 기록 선택 → 본문 옆 휴지통. 뒤에 이어진 기록이나 다른 작성안의 참조가 없는 끝 스냅샷만 삭제할 수 있습니다. 현재 초안 본문은 남습니다.
- 왼쪽 ‘작성안 관리’에서 작성안을 삭제할 수 있습니다. 대상 기록과 초안 개수를 확인하며 마지막 작성안은 유지합니다. 다른 작성안과 제출본, 조합 때 복사한 출처 본문은 보존합니다.
- 수동 ‘작성 중 닫기’ 기능은 없습니다. 최신 원문과 같아지거나 스냅샷을 남기면 작성 중 표시가 사라집니다.

## 연결 상태

실제 서버 인증·Google/카카오 OAuth·메일 발송·공고 URL 수집·이미지 OCR·AI API/MCP는 아직 연결하지 않았습니다. 각 화면에 연결 전 상태를 표시합니다. 인증 화면은 전환·유효성 확인용이며 비밀번호는 저장하지 않습니다. 회원가입 화면의 미리보기 인증번호는 `123456`입니다.

주간 공고 추천·실시간 음성 면접은 후속 범위이며 이 프론트에 구현하지 않았습니다.

## 보관과 백업

- 문서·기록·일정·제출본: 이 브라우저의 localStorage (`janovel.frontend.v1`).
- 첨부 이미지: IndexedDB (`janovel-attachments`).
- 상단 백업에서 JSON 내보내기·검증 후 불러오기. JSON은 이미지 파일을 포함하지 않습니다.
- 저장 실패는 화면에 표시합니다. 손상된 기존 저장 데이터는 자동 덮어쓰기하지 않습니다.
- 브라우저 저장 공간 삭제·다른 기기로 이동 전에 백업하세요.

## 검증

```sh
npm --prefix frontend test
npm --prefix frontend run build
```

Node 모델 테스트는 불변 스냅샷, 자동 분기, 초안 충돌, 두 병합 방식, 그래프 부모 연결, 고정본 분리, 공고 문항 입력, 지연된 메시지의 최신 편집 보존, 백업 데이터 검증을 확인합니다. 두 칸 비교의 부분 반영·연속 클릭·반복 문구와 활성 초안 표시·보존도 검증합니다.

기록 정리 테스트는 끝 기록 삭제 제한, 다른 분기·병합 참조 보존, 활성·마지막 분기 삭제, 닫기·재편집, 빈 본문, 스냅샷 번호 중복과 반복 병합 그래프의 삭제 처리 시간을 확인합니다.

독립 작성안 테스트는 빈 작성안 생성·이름 수정·과거 기록의 동일 작성안 편집·기존 초안 충돌·원본 무변경 조합·출처 보존·새로고침 시 비교 대상 보존을 확인합니다. 기존 분기 API 테스트는 저장 데이터 호환성을 위해 남아 있습니다.
